## Purpose

The deterministic pre-AI and post-AI safety layer. It intercepts post text and comment text before (and independently of) any AI call, matching slur dictionaries, profanity dictionaries, dehumanization compound patterns, coded structural harm patterns (self-harm imperatives, solicitation, doxxing, scapegoating, clickbait), and harm-laundering detection on rewrites. It also scores text with a weighted harm-floor signal model (0-100) that functions as a fallback verdict when AI is off/failed. The layer is fail-closed: deterministic protections (slur match, dehumanization, coded-harm) fire whether or not the AI provider is reachable.

## Inputs

Post text (string) + mode (child/teen/adult) from pipeline settings; L1 TechniqueResult[] from the techniques cascade (passed to computeHarmFloor; may be [] for comment-path or free-tier); rewritten text string (harm-laundering check in content/index.ts); comment CommentNode[] array (enrichWithHarmFloor in comment-batch-scorer.ts). ## Outputs

Post-level: PipelineResult with action='hide'/'collapse'/'neutralize' + AnalysisResult synthetic verdicts. Comment-level: enriched CommentNode[] with harm_floor: CommentHarmFloor on each child; BatchCommentVerdict[] from failClosed fallback (when the AI call fails). Rewrite-path: boolean detectHarmLaundering result routing a passing rewrite back to 'hide'. All outputs feed src/analysis/pipeline.ts step returns, src/analysis/comment-batch-scorer.ts scoreBatch/failClosed, and src/content/index.ts action dispatch.

## Invariants & contracts

- Slur filter runs for ALL modes (child/teen/adult) unconditionally; a match always routes to action='hide' regardless of AI state.
- Matching is LANGUAGE-BLIND: the four global dictionaries are one union and there is no post-language gate. lang-detect.ts distinguishes only en/ro/mixed/unknown, is deliberately generous about 'mixed' and is weakest on short posts, so a gate would disable protection more often than it prevented a false positive. Cross-language collisions are handled per term (an exception, an exact-only entry, or a language withdrawal), each with the count that justified it.
- Matching IS region-aware, on the READER's locale rather than the writer's text: navigator.language ('es-PE', 'pt-BR') is exact, free, needs no inference and has no short-post problem. An unknown region fires nothing region-dependent, which fails towards showing a post rather than hiding one. setReaderRegion() overrides it (the user's own interface-language choice is a stronger signal than the browser default). Nothing about the reader's region is recorded, sent to the worker, or leaves the device.
- The two tiers do not share an evidence bar. A wrong PROFANITY entry stars a word; a wrong SLURS entry hides the whole post and the reader never learns it existed. Ambiguous terms go in the profanity tier or nowhere: 'marica' is homophobic but is also a given name and a Colombian filler, so it stars rather than hides.
- filterProfanity returns cleanText built from the ORIGINAL string, not the folded one, with each match replaced by the same number of characters it covered. cleanText.length === text.length always, and text outside a match is byte-identical. Before 2026-09-04 the output was built from the folded text, so any match anywhere returned a post with every diacritic stripped ("Qué mierda, mañana" → "Que ****** manana"); Off's word filter writes cleanText straight back into the page, so that was user-visible in the free product.
- Spanish and Portuguese self-harm imperatives lean on grammar rather than on a guard where they can. Spanish puts the reflexive pronoun on the END of an affirmative imperative ('matate') and in FRONT of a negated one ('no te mates'), so the two forms share no spelling and the negation cannot collide. Portuguese keeps the word order ('nao se mate' vs 'se mate'), so it needs the preceding-negation guard; and its proclitic form doubles as the third-person subjunctive ('espero que se mate' is a worry about someone else, Don Quijote has 'estamos se mate por causas tan livianas'), so the proclitic form must open its clause, while the hyphenated enclitic 'mate-se' needs no guard because Portuguese orthography only ever hyphenates an imperative.
- 'vai te matar' is NOT a self-harm rule. It means "will kill YOU": a threat or an idiom ("Dizer 'por favor' vai te matar?"). Only 'vai se matar' is.
- A token with no letters in it can never match. The leet fold maps digits to letters, so '455' became 'ass' and fired on every post containing that number, in every language (found 2026-09-04).
- Harm-floor (computeHarmFloor) and slur filter both run BEFORE the free-tier short-circuit (`tierCap === 0`) in pipeline.ts:process; deterministic protections cannot be bypassed by an exhausted cap.
- enrichWithHarmFloor calls computeHarmFloor(text, []) (comment-batch-scorer.ts:enrichWithHarmFloor) so only categories A/B/C/D/E/I (text-only signals, max ~80) contribute per-comment; no L1 TechniqueResult[] feed-in at comment level.
- failClosed fallback reproduces the same override logic (identity-slur → sev=8/hide; coded-harm → category severity; HF≥70 → sev 7/8/9) so the deterministic floor is verdict-symmetric with the AI-success path (comment-batch-scorer.ts:failClosed).
- detectCodedHarm is NFKD-fold-first (coded-harm-catcher.ts:detectCodedHarm) so Romanian directed-harm imperatives match despite diacritics.
- Harm-laundering check (detectHarmLaundering) is called on the comment rewrite path (content/index.ts flushBatch rewrite pass) AND on the post-level blanket profanity-soften branch in pipeline.ts (gates the neutralizeText rewrite before it ships).
- IDENTITY_SLUR_WEIGHT=50 ensures a bare identity slur (e.g. 'nigger' alone) reaches totalScore=50 in enrichWithHarmFloor, which is BELOW the HF≥70 failClosed severity-floor gate — but the identity_slur_match flag is checked separately in failClosed so it still routes to hide-tier.
- Calibration (calibration.ts) computes a suggestedThreshold but never WRITES it to storage automatically — getEffectiveThreshold reads chrome.storage.local; the write must be triggered externally. No pipeline code calls calibrate() to auto-apply.

- Legacy pre-rewrite comment hides (`video-pipeline.ts`) prefer the extractor's live row reference and require exact full text. Without that reference, an available author must match one exact-text entry; only a missing author permits a unique exact-text fallback. `hideCommentAsFallbackTerminal` proves the DOM is hidden before `recordedCommentHideAction` records `hide`; an absent or ambiguous match records `mark`.

## How it SHOULD work

Text enters at the parent blocklist gate (above the dedup cache) then pipeline Step 0a (slur filter) → Step 0a.1 (coded-harm hide tier, all modes and tiers) → the sponsored gate (collapse in every mode; category-only on Adult) → Step 0b (profanity filter; child hide, then the too-short reject, then the toggle-driven soften) → Step 0c (dehumanization filter) → Step 0c.1 (violence-narrating video gate, child and teen) → Step 1.5 (harm-floor weighted scorer). Each step can short-circuit to action='hide' or 'collapse' before the LLM is reached. On the comment-batch path, enrichWithHarmFloor pre-annotates each CommentNode with a harm_floor struct (score + top_category + identity_slur_match), which then drives: (a) the post-AI applyOverrideGates per-comment adjuster that can escalate or override a low LLM verdict, and (b) the failClosed fallback when the AI provider is unreachable or the call fails. detectHarmLaundering guards the rewrite step so violence-scrubbing rewrites are rejected. There is no third lexicon path: the dsojevic-derived matcher that once sat beside profanity-filter.ts was deleted unused.

## How it ACTUALLY works

Post-level pipeline.ts (src/analysis/pipeline.ts): the parent blocklist runs FIRST, above the dedup cache: `activeParentBlocklist(settings.features)` + `matchParentBlocklist(list, post.text, post.author)` from core/parent-blocklist.ts. On a hit it returns action='hide' with detectionMode `blocklist:<word|phrase|account>:<rule>`, isManipulative=false and empty techniques (it obeyed an instruction, it did not judge; the same rule-only shape as the adult sponsored-ad branch). It sits above the cache because the cache key carries no blocklist dimension, so a post cached before the parent added a rule would keep its old verdict; it applies in every mode and on the free tier, because the adult carve-out and the paywall are both about AI guesses. Then Step 0a calls filterProfanity(post.text, mode, {tier:'slurs'}): ALL modes, returns hide if filtered. Step 0a.1 calls detectCodedHarm(post.text); a hide-tier category returns hide through codedHarmVerdictFields, in every mode and on every tier. The sponsored gate follows (collapse; Adult gets the category-only analysis, see ai-pipeline.md). Step 0b calls filterProfanity(post.text, mode, {tier:'profanity'}): hides only for child mode; then the too-short / non-substantive reject (MIN_TEXT_LENGTH 12, under 3 words) returns pass; then the soften path runs when `blanketProfanitySoften(settings, platform)` (the `soften-swearing` toggle with its per-platform override, OR `strictLanguage`; mode reaches it only through the presets that seed the toggle) AND `softenAiAllowed` (paid tier, breaker not holding, daily and monthly caps) both hold, and its rewrite is re-checked by the dehumanization, violence and laundering gates before it ships. Step 0c calls detectDehumanization(post.text): returns hide for all modes. Step 0c.1 calls detectViolenceNarratingVideo (gated on kind==='video' and child or teen). Step 1.5 calls computeHarmFloor(post.text, techniques): triggers collapse when score≥70 AND detected.length===0. Free-tier short-circuit fires AFTER all these steps. Comment-batch path (comment-batch-scorer.ts): enrichWithHarmFloor maps over encounter.children and for each calls computeHarmFloor(c.text, []) + filterProfanity(c.text, 'teen', {tier:'slurs'}) + detectEmojiPile + detectRepetition; combines into totalScore = min(100, hf.score + slurBonus + emojiWeight + repetitionWeight). Then computePreLlmRoomSignals aggregates per-comment harm_floor scores into toxicityScore and slurPrevalencePct for the BATCH prompt. After the AI returns, applyOverrideGates checks identity_slur_match → child profanity floor → profanity tier (sev≥8) → coded-harm → rage-format → HF≥70 → ad-hominem in that priority order (seven gates) and escalates verdicts; the absent-target downgrade lives in scoreBatch's normalize loop, not here. When the AI call fails, failClosed re-runs identity-slur check, detectCodedHarm, and HF≥70 directly from enriched harm_floor data. Rewrite path (content/index.ts flushBatch rewrite pass): detectDehumanization and detectHarmLaundering are called per-comment before accepting any AI rewrite, and a laundered rewrite routes to hide.

The legacy video-comment path uses `applyUniquePreRewriteHide`: a live extractor row plus exact full text selects the entry first. Without a live row, an available author must match one exact-text entry; only a missing author permits a unique exact-text fallback. The hidden terminal must be proven before the forensic action is recorded as `hide`. A missing or ambiguous target is recorded as `mark`.

The dashboard Statistics panel renders this fixed state; nothing auto-adjusts thresholds on the parent's device. — src/core/calibration.ts
- **[low]** RAGE_FORMAT_OPENING regex in applyOverrideGates (comment-batch-scorer.ts) fires on comments, not just posts — a comment starting with 'BREAKING' that the LLM scored sev<6 escalates to misleading-format sev=6. This pattern was corpus-tuned on post-level data (honest-en-v1) and its comment-level FP rate is unmeasured. — src/analysis/comment-batch-scorer.ts:applyOverrideGates
- **[low]** profanity-filter.ts Teen mode: filterProfanity with tier='profanity' and mode='teen' sets shouldReplace=false (mode !== 'child'). So profanity matches in teen mode flag only (matches[] populated) but DO NOT modify cleanText.
