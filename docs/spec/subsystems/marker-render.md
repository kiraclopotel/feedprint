# Subsystem: marker-render

> Traced from code. Confirmed defects live in the defect register `known-issues.md`, which is not part of the public copy; [KNOWN-LIMITS.md](../KNOWN-LIMITS.md) carries what a reader outside the project needs from it. Re-read against the code in the 2026-08-23 objective audit (spec-drift.md items 73 to 78); cites are symbols, not line numbers.

## Purpose

Converts a pipeline verdict (AnalysisResult / NeutralizedContent / a validated batch rewrite) into the visible, interactive DOM change the user sees: an in-place comment text swap, a severity-colored dot button (the teen marker), and a collapse/hide placeholder. Also captures per-record engagement metrics for the forensic chain and operates the runtime heap/activity diagnostics used to detect memory leaks. This subsystem is the FINAL rendering step: nothing downstream consumes its output, and since 2026-08-23 every render path ends in a terminal proof (see "Terminal proof" below) before the record is written.

## Key files

- src/content/markers/teen-marker.ts - Core marker renderer. Exports: renderTeenMarker (main entry — mounts a 28x28 button.fw-teen-marker with a 14px severity dot), pickYellowReason (LLM-reason guard chain), resyncMarkerToGreen (replay resync), removeAllTeenMarkers (toggle-off teardown). Internal: attachStateToggle (3-state GREEN/YELLOW/RED semaphore), attachTwoStateToggle (2-state, resting state 'base'). Also injects the fw-teen-marker-styles <style> block through its private `ensureStyles()` (DOM presence is the only skip condition); this is the only marker CSS, there is no `injectStyles` anywhere in src.
- src/content/markers/ai-mark.ts - The machine-readable mark on text an AI model wrote. Exports: AI_TEXT_ATTR (`data-fw-ai-generated`, value `rewrite` or `reading`), AI_MODEL_ATTR (`data-fw-ai-model`), markAiText, clearRewriteMarks, rewriteChangesText, writerOfRewrite. See "Machine-readable AI mark" under the invariants.
- src/content/markers/read-this.ts - The on-demand reading's answer card (`div[data-fw-read-answer]`, its own style tag `fw-read-answer-styles`, mounted after the item's text scope); not a marker and not a swap: the item's text is untouched. Spec: `read-this.md`.
- src/content/protection/comment-overlay.ts - In-place comment text swap. Exports: findCommentEntries, buildCommentEntryForRoot, swapCommentTextInPlace, hideCommentAsFallback, hideCommentAsFallbackTerminal, recordedCommentHideAction. There is no comment orchestrator in this file: the comment path is flushBatch -> marker loop -> pendingSwaps -> applyCommentRewriteTerminal (content/index.ts).
- src/content/injector.ts - Post-level injection orchestrator. Exports: injectIntoElement (rewrite path), injectCollapseOrHide (collapse/hide placeholder path), markOnlyElement (mark-only with empty rewrite), injectAdHide (full ad removal), injectHardHide (silent full removal for a hard `hide` — display:none on the per-platform feed container, no placeholder, no gap, `data-fw-hard-hidden`, distinct from ad-hide; the owner 2026-06-19). It silences media and notes an Instagram ad slot through src/content/hide-primitives.ts (muteAndPauseMedia, noteAdSlot), which the engagement ad blockers import directly so Off does not load this file. A successful TikTok ad hide also records the card root and strict wrapper id through `tiktok-ad-remount.ts`; this runtime-only state lets the adapter reprocess one exact sponsored rehydration if TikTok removes the hide attributes. Also owns addGuard (MutationObserver rewrite defender, MAX_GUARDS=500) and replaceText (span-aware text swap with typography preservation). Injects global CSS via injectStyles().
- src/content/record/record-metrics.ts - PostContent → RecordMetrics normalization for the forensic chain. Exports: recordMetricsFromPostContent. Handles X replies/quoteTweets rename, Instagram obscured-likes, Facebook postReactions/postCommentsCount/postShares caption vs comment split.
- src/content/fw-log.ts - Debug-log gate. Exports: fwDebug, fwDebugDebug. Gated behind globalThis.__FW_DEBUG__ boolean; production silent by default.
- src/diagnostics/diagnostics.ts - Runtime heap + activity monitoring. Exports: startDiagnostics, sampleHeapNow, usedHeapMB, bumpCounter, setGaugePeak, coerceMultiHost, readDiagnosticsResult (there is no `readDiagnostics`), aggregateDiagnosticCounters, aggregateDiagnosticCounterFirstSeen, pickWorstClimbingSnapshot, pruneDiagnosticHeapSessions, flushDiagnosticsNow, summarizeHeapTrend, and the post-intervention receipts beginPostIntervention / finishPostIntervention / notePostPassAfterIntervention (each hide / collapse attempt reports requested plus one terminal applied / suppressed / failed disposition, the accepted / retry / dedup / context receipt, concurrent same-post overlap, and any post-LLM PASS for that post within 60 s). Persists bounded full heap snapshots plus lightweight counters per opaque content-script session to chrome.storage.local fw_diagnostics every 5s (debounced). Every counter also carries the epoch ms of its FIRST bump in that session (counterFirstSeen, optional so pre-existing sessions still merge); the read aggregates it as the earliest stamp per counter and the dashboard exports it as diagnosticCounterFirstSeen. That stamp is the age of the instrument: a day total from a counter shipped an hour ago and a day total from a counter running since midnight are not comparable, and reading them as a pair fabricated two defects on 2026-08-02. Dashboard reads the worst heap session separately from the all-session counter totals.
- src/content/post-path/dom-recycle-recovery.ts - the render-gate recovery family: tryRecoverDomRecycledAnchor (post rewrite / mark), tryRecoverExactPostInterventionAnchor (hide / collapse: the same real platform id, full body and known author inside the post's remembered feed area, once now and once next frame), tryRecoverCommentAnchor (marker / swap loop) and tryRecoverCommentHideAnchor (Facebook-only, one unique exact full-text + depth + author candidate inside the parent post)
- src/content/probes/hide-chip-probe.ts - noteHideChipMounted: counts the show-anyway notice chips the hard-hide path mounts (the M96 probe)
- src/content/protection/child-first-protection.ts - ChildProtectionManager (protect / prepareMutation / commit / release / pruneStale): the provisional cover lease every render path holds in Child; src/content/protection/settle-protection.ts createProtectionSettler is the one terminal through which a cover is released (record 'batch', 'post', 'unrecorded-fail-open' ...)
- src/diagnostics/selector-health.ts - Selector drift counter. Exports: recordSelectorMiss, recordSelectorHit, recordSelectorOutcome, flushNow, readSelectorHealth, assessPlatformDrift, overlayCanary. Flushes to chrome.storage.local fw_selector_health every 30s.

## Inputs

From content/index.ts (the pipeline orchestrator): NeutralizedContent (rewrittenText + AnalysisResult), AnalysisResult (for mark/collapse/hide paths), PostContent (for recordMetricsFromPostContent), validated batch rewrites (for the pendingSwaps loop). Settings flags: show-reframe-markers toggle (per platform, read in index.ts), uiLanguage. Also receives platform string and Mode. From comment-overlay.ts path: raw DOM elements (commentsContainer, rootEl) holding live comment nodes.

## Outputs

To DOM: modified textContent on post/comment body elements, inserted button.fw-teen-marker nodes, data-fw-* dataset stamps (data-fw-neutralized, data-fw-rewritten, data-fw-action, data-fw-marker-state incl. the 'base' value, data-fw-technique, data-fw-sarcasm, data-fw-hidden-fallback, data-fw-ad-hidden, data-fw-hidden-media; data-fw-original/-original-text no longer exist), and the machine-readable AI mark data-fw-ai-generated + data-fw-ai-model on the element holding a model's rewrite and on the reading card. Aria: the state-specific aria-label is the marker's single accessibility channel (aria-expanded/aria-pressed removed — a 3-state cycle is not a two-state toggle). To forensic chain (via content/index.ts → FORENSIC_LOG message): RecordMetrics object attached to the chain record. To chrome.storage.local: fw_diagnostics (heap + counters) and fw_selector_health (selector miss counts).

## Invariants & contracts

- Idempotency on teen-marker (revised 2026-08-11): descendant query for 'inside' mounts; for 'after' mounts the markerByElement WeakMap is the identity authority (a connected prior marker blocks re-mount even when the platform inserted nodes between body and dot; a detached one allows the virtualizer-remount re-mount), with a bounded sibling scan as cross-realm fallback. Empty-base rewrite markers are skipped entirely and rewrite-less bodies use the mark-only posture. Lock: tests/unit/content/markers/marker-mount-honesty.test.ts.
- Guard skip when user has toggled (revised 2026-08-11): addGuard's observer returns early ONLY on the explicit user states 'yellow'/'red'. The two-state toggle's resting stamp is the distinct value 'base' (never 'red'), so the guard defends both the rewrite ('green') and the calm placeholder ('base') against platform re-renders; the old `!== 'green'` skip disarmed the guard on every folded post. Replay path: when injectTeen finds an existing marker after re-swapping the rewrite, resyncMarkerToGreen re-aligns state/dot/aria. Lock: tests/unit/content/markers/marker-guard-state.test.ts.
- Rewrite guard MAX cap: guardOrder is pruned of disconnected elements on every addGuard call; overflow cap is 500, enforced by eviction of oldest. Teardown (2026-08-11): releaseAllGuards() drops every observer + strong ref on interceptor.stop(); a show-reframe-markers flip removes mounted dots via removeAllTeenMarkers() (features invalidation path) while rewrites and guards stay - the marker is UI, the rewrite is protection. Style block: the DOM element is the only injection authority (the unrecoverable module latch is gone); a replaced head heals on the next marker. Lock: tests/unit/content/markers/marker-teardown.test.ts.
- Collapse/hide originals (revised 2026-08-11): the forensic chain is the only original-content store. The data-fw-original / data-fw-original-text attribute copies were deleted (written on three paths, read by nothing; the marker's RED state restores from its closure-bound originalText). The old "fold is reversible via the attribute" claim had no implementing reader and is retired.
- mark-only with empty rewriteText: renderTeenMarker mounts the two-state toggle with the RED base (attachTwoStateToggle, resting state 'base'), never the broken 3-state cycle; it returns null only when there is no base text to restore, on idempotency, or on an inspection tab.
- Typography preservation: both replaceText (injector.ts) and swapCommentTextInPlace (comment-overlay.ts) snapshot computed color/font from the deepest text-bearing node before mutating. Failure is caught and swapped to null (defensive).
- hideCommentAsFallback stamps data-fw-hidden-fallback='true' in addition to data-fw-rewritten='true' to distinguish hide-on-failure from swap-on-success (comment-overlay.ts).
- TikTok ad-remount state is card-scoped and runtime-only. It is created only after `injectAdHide` resolves the full TikTok feed card and applies the hide. An exact same-id sponsored rehydration can claim it once; another successful hide rearms it. Changed or unsafe sponsored identities are processed once as fresh records, while another root, an organic card, or a never-hidden card cannot claim the state.
- Metrics omit-when-nothing: recordMetricsFromPostContent returns undefined (not {}) when no fields are captured so metric-less records hash byte-identically to legacy records (record-metrics.ts).
- Diagnostics persist per content-script session: two tabs on the same host keep distinct opaque session slots. Full heap history is capped at 20 sessions, reserving half the slots for highest-risk traces and filling the rest by recency so later calm tabs cannot erase a captured climb; lightweight daily counter snapshots are capped at 200 and summed for Issues, so the memory-risk host selection cannot hide another tab's media failure counter. Existing hostname-keyed heap and counter data migrate under aligned IDs before pruning.
- Inspection pass (dashboard-opened tabs): `isInspectionTab()` (src/content/post-path/inspection-mode.ts) answers true for either of the two inspection modes the SW grants, `'reveal'` (View original) or `'observe'` (metrics recheck); every DOM intervention applier is gated on it — injectIntoElement, markOnlyElement, injectCollapseOrHide, injectAdHide, injectHardHide, renderTeenMarker, swapCommentTextInPlace, hideCommentAsFallback(Terminal), and the provisional cover (ChildProtectionManager.protect) all no-op so the parent's "View original" tab and the metrics-recheck tab show the post untouched. Extraction, scanning, forensic logging, and metrics capture keep running; records on such tabs honestly carry action 'mark'/hideApplied=false. The flag comes only from the SW inspection-tab registry (dashboard actions only) and fails closed: any error or malformed response means full protection. Engagement hiding and the transient document-start shield are deliberately NOT gated (chrome-level count hiding does not obstruct inspection; the startup shield lifts at content-ready).
- Hard-hide notice guard and re-assert budget (injector.ts): a hard hide on Teen / Adult mounts a one-line show-anyway / hide-again notice chip (`mountHideNotice`, counted by hide-chip-probe) and arms a guard that re-asserts `display:none` when the platform restores the container; the guard spends at most MAX_HIDE_REASSERTS (3) within HIDE_REASSERT_WINDOW_MS (10 s) on one container, bumps `hardHideReasserted` on each re-assert, and withdraws the notice (`hardHideNoticeWithdrawn`) once the budget is spent, so a fight with the platform ends loud rather than looping; a user reveal outranks the guard (known-issues M97: a stale reveal attribute yields to the post's own truth).
- Machine-readable AI mark (src/content/markers/ai-mark.ts): the EU AI Act, Article 50(2), asks that text an AI system writes or rewrites be marked in a form software can read, and Regulation (EU) 2026/1744 adds Article 111(4): a system placed on the market before 2 August 2026 must meet Article 50(2) by 2 December 2026. The visible dot shows only when show-reframe-markers is on, so every element that holds a model's words carries `data-fw-ai-generated` naming the kind of text (`rewrite`, or `reading` on the Read this for me card) and `data-fw-ai-model` naming the model the call's reply named (absent when no reply named one). The mark follows the element's text: injectTeen sets it once a model's rewrite that changes the words is visible on the page (a swear mask, `aiSource: 'rules'`, and a rewrite equal to the original are not marked; when the platform's text setter drops the write, injectTeen returns false and clears any mark, so the author's words are never marked and Child's hide fallback hides an unmarked post); applyCommentRewriteTerminal sets it on the comment's text element when a swap from a model lands, and a replay of a resolved comment carries the same writer; swapCommentTextInPlace clears it, because it also writes hide notices, the original on a reveal and masks; applyActionPlaceholder clears it when a rewritten post is folded; the marker toggle sets it on GREEN (or the base state when that is the rewrite) and clears it on RED, YELLOW and every other base; rendering a marker never sets it, because on the comment path the marker mounts before the swap. Hard hides, ad hides and hidden comment rows are not marked. The writer is `NeutralizedContent.writerModel` (pipeline.ts: the rewrite call's reply on the adult path, where the judge is another model; on Teen and Child the reply to the judge's classify call, which carries the rewrite, read with `latestModelFor` in src/ai/call-provenance.ts so the triage call before it is not named; kept through the processing cache), and on the comment path the batch reply for an inline rewrite (the retry's, when a cut reply was asked again) or the rewrite call's reply (neutralize-only.ts `onWriter`). The record names the same writer as `decision.rewrite.model` when the rewrite landed (content/record/decision.ts rewriteStage). A Teen or Child post's record has no decision block, and its `aiModel` names every model that answered the judge's calls, triage and classify, joined with '+': the writer is among them, and is the only one when one model answered both. Not marked, and known: the marker's YELLOW line can show the judge's own one-line reason, and nothing on that path says whether an explanation came from a model or from a fixed rule, so YELLOW clears the rewrite mark and adds none. Locks: tests/unit/content/markers/ai-generated-mark.test.ts, tests/unit/content/comment-batch/a-rewritten-comment-carries-the-ai-mark.test.ts, tests/unit/content/markers/read-this.test.ts, tests/unit/analysis/pipeline-record-names-the-judge.test.ts.
- data-fw-essential guard on marker button: marker.setAttribute('data-fw-essential','true') (teen-marker.ts:renderTeenMarker) prevents the engagement structural-finder from hiding FW's own affordance.
- Ad hide is platform-aware (measured live 2026-08-11): on Instagram `injectAdHide` uses `visibility:hidden !important` and NEVER touches display, because IG's windowed feed positions and loads from its own height bookkeeping and removing the article's box truncated the entire feed below the ad (the long-standing "posts disappear" recurrence: user parked in the wrapper's reserved padding, all rendered articles above the viewport). Both `injectAdHide` and `injectHardHide` now also stamp `data-fw-block-reason` ('ad-hide' / 'hard-hide') per the name-your-circuit contract — the live triage took two probe rounds because the ad path stamped only its own attribute. ## How it SHOULD work

Pipeline result arrives at content/index.ts. After the AI/rules verdict, index.ts calls one of three injector entry points depending on action: injectIntoElement (rewrite), injectCollapseOrHide (fold/hide), or markOnlyElement (mark-only). Each entry point: (1) snapshots original innerHTML/text, (2) calls replaceText or applyActionPlaceholder to swap visible content, (3) arms a MutationObserver guard to re-apply on platform re-render, (4) calls renderTeenMarker if show-reframe-markers is ON. renderTeenMarker mounts a severity-colored 28x28 button whose dot color encodes the current state of a 3-state cycle (GREEN=rewrite, YELLOW=why, RED=original). For comment batches, the flushBatch marker loop and pendingSwaps loop do the same through applyCommentRewriteTerminal. Old text: injectTeenRewrittenComments handles in-place text swap and marker placement across all platforms. recordMetricsFromPostContent runs on every FORENSIC_LOG write, normalizing platform-specific engagement counts into a canonical shape. startDiagnostics starts a 30s heap sampler + bumpCounter/setGaugePeak record activity on the interceptor hot path.

## How it ACTUALLY works

1. content/index.ts — startDiagnostics() called once on adapter init (after platform is resolved). Heap sampling begins immediately.

2. Post result dispatch in index.ts `onProcessingResult`: verifyAnchorMatch confirms the DOM element still holds the original text. On 'dom-recycled', tryRecoverDomRecycledAnchor (post rewrite / mark) or tryRecoverExactPostInterventionAnchor (hide / collapse) is attempted. On failure, render is suppressed and the record carries the cancel verdict. Each attempt opens a post-intervention receipt (beginPostIntervention) that finishPostIntervention closes with one terminal disposition.

3. On action='neutralize': index.ts calls `applyNeutralizedRewriteTerminal(post, el, neutralized, showMarkers)` (showMarkers comes from the `show-reframe-markers` toggle), which calls injectIntoElement(el, neutralized, mode, showMarkers, post.text, lang). Inside injector.ts: the inspection-tab gate, `isInViewport`, then injectTeen: replaceText(el, neutralized.rewrittenText) → addGuard(el, rewrittenText) → return false when the rewrite is not visible → if showMarkers: renderTeenMarker with kind='rewrite', rewriteText=neutralized.rewrittenText, analysis=neutralized.analysis (the marker renders whenever the toggle is on, regardless of whether the rewrite text equals the original). Nothing is stamped on the element but the data-fw-* state attributes, including the machine-readable AI mark when a model wrote the rewrite and it is visible.

4. replaceText (injector.ts): disconnects existing guard, snapshots computed style of the deepest text-bearing child via TreeWalker, then walks childNodes placing text in the first text-node or SPAN, hides extra SPANs and all A/IMG children, applies inline color+font, re-observes guard.

5. renderTeenMarker (teen-marker.ts): checks idempotency, `ensureStyles()`, computes severityColor from analysis.overallScore, creates button.fw-teen-marker.fw-marker-entry with data-fw-essential='true' and the --fw-marker-color CSS var. Branches on kind+rewriteText: full 3-state (attachStateToggle) when kind='rewrite' AND originalText non-empty AND rewriteText non-empty; 2-state mark-only (attachTwoStateToggle with baseColor=RED_COLOR) when isMarkOnly; 2-state collapse (attachTwoStateToggle with baseColor=FOLDED_COLOR); 2-state fallback with GREEN_COLOR. Appends to el (inside) or el.after() per mount.

6. On action='collapse'/'hide': index.ts `applyCollapseHideVisual` first routes a hard `hide` to `injectHardHide` (display:none on the per-platform feed container; Instagram keeps the box with visibility:hidden; no placeholder, no marker, no gap; the forensic record still emits separately); only on no-container-resolved (or for `collapse`) does it fall to the placeholder path: injectCollapseOrHide removes any stale fw-teen-marker children, computes reasonTextFor(kind, analysis, lang), calls applyActionPlaceholder (replaceText + data stamps + hidePostMedia + addGuard), then renderTeenMarker with kind='collapse'. Both paths end in the `replacementIsVisible` post-condition; a false return means the visual did not land.

7. On action='mark': index.ts calls markOnlyElement, which calls renderTeenMarker with rewriteText='' → isMarkOnly → the two-state RED-base toggle.

8. Comment batch path (index.ts flushBatch): the marker loop resolves each flagged comment's element once (verification + tryRecoverCommentAnchor), publishes it into `resolvedAnchorByPost`, and calls renderTeenMarker with mount='after' for TikTok and 'inside' for others. Hide-tier verdicts go through `applyCommentHide` (prepareCurrentPostMutation → hideCommentAsFallbackTerminal → proven `display:none` + `data-fw-hidden-fallback` → recordedCommentHideAction). THEN the pendingSwaps loop reuses the resolved anchor and calls `applyCommentRewriteTerminal` (swapCommentTextInPlace + saved-marker re-append + replacementIsVisible).

9. There is no separate TikTok comment render path: video-pipeline.ts's legacy pre-rewrite hides go through `applyUniquePreRewriteHide` and the same hideCommentAsFallbackTerminal; rewrites and markers for every platform mount through step 8.

10. recordMetricsFromPostContent is called on every FORENSIC_LOG payload head (content/forensic-emit.ts postPayloadBase and the remaining literal sites in index.ts). Normalizes PostContent.platform_specific into RecordMetrics, omits undefined keys, returns undefined when nothing captured (record-metrics.ts).

11. bumpCounter/setGaugePeak: interceptor.ts bumps the overflow-drop, batches-drained and peak-nodes counters; injector.ts bumps exactly two, `hardHideReasserted` and `hardHideNoticeWithdrawn`; teen-marker.ts bumps none. Per-render volume is otherwise visible only through the post-intervention receipts and the heap trend.

## Terminal proof

Every render path ends in a proof that the protection reached the screen, and the record is written from that proof, never from intent:

- `replacementIsVisible(el, expectedText)` (injector.ts) is the post-condition of injectIntoElement and injectCollapseOrHide: the element is connected and its visible text is the replacement.
- `applyNeutralizedRewriteTerminal` (index.ts): rewrite path for posts. On success it commits the Child cover (`commitProtection`); on failure in Child it converts the failed rewrite into a hide through the same collapse/hide visual and commits, and when that visual also fails it RETAINS the provisional cover and records `visualApplied:false` rather than uncovering (commit 3d4c368); in Teen / Adult a failure releases.
- `applyCommentRewriteTerminal` (index.ts): the comment swap with the same proof; a Child failure hides the row instead; the rewrite FORENSIC_LOG is still emitted before this terminal runs, so a rewrite record can precede a later safety hide (known-issues M61).
- `applyCommentHide` (index.ts): prepareCurrentPostMutation moves the Child cover to the exact remount, then hideCommentAsFallbackTerminal proves the hidden state before `recordedCommentHideAction` records `hide`; a miss records `mark` and keeps the cover.
- `prepareCurrentPostMutation(post, replacementAnchor?)` (index.ts): the ChildProtectionManager lease check every mutation takes first; a stale lease (route moved, ticket superseded) refuses the mutation.
- `ChildProtectionManager` (child-first-protection.ts): protect / prepareMutation / commit / release / pruneStale around every path; `settleProtection` (settle-protection.ts createProtectionSettler) is the single release terminal, called with a record kind so a release without a chain record is named (`unrecorded-fail-open`), never silent. The collapse / hide post path and the neutralize path now share this rule (commit ee6d70d; the earlier asymmetry where a failed collapse visual released the cover is closed, known-issues M108).
- `rememberResolvedComment` and `storeLateVerdict` (late-verdict-cache.ts): a proven hide or validated rewrite enters `sessionCommentResolutionByKey`, and a late post verdict enters `sessionHideCollapseByPostId`, so a virtualizer remount replays the proven outcome on the fresh node instead of re-judging.

## Data flow (through this subsystem)

1. Pipeline verdict (AnalysisResult + NeutralizedContent) → content/index.ts onProcessingResult → verifyAnchorMatch → el (live DOM element, deref'd WeakRef or recovered anchor via dom-recycle-recovery.ts)
2. el + NeutralizedContent → applyNeutralizedRewriteTerminal → injectIntoElement (injector.ts) → injectTeen
3. injectTeen → replaceText(el, rewrittenText) → DOM: el.childNodes mutated, inline style applied, original text gone from view
4. injectTeen → addGuard(el, rewrittenText) → MutationObserver armed on el (fires if platform re-renders, restores rewrittenText unless fwMarkerState != 'green')
5. injectTeen (if showMarkers) → renderTeenMarker({el, analysis, originalText, kind:'rewrite', rewriteText}) (teen-marker.ts) → button.fw-teen-marker appended to el (or el.after()); click handler wired to 3-state semaphore via attachStateToggle
5b. injectIntoElement → replacementIsVisible(el, rewrittenText) → true: commitProtection; false in Child: applyCollapseHideVisual then commit or retain; false in Teen / Adult: settleProtection
6. Click on button.fw-teen-marker → attachStateToggle click handler → NEXT_STATE cycle → findTextHolder → holder.textContent = {rewriteText|originalText|reasonBodyText} → --fw-marker-color updated → aria-label updated → fwMarkerState stamped on bodyEl.dataset
7. pickYellowReason(analysis, lang) (teen-marker.ts) → validates groqReason via length/language/advisory/echo guards → returns LLM reason or static MARKER_REASONS[lang][technique] fallback
8. PostContent → recordMetricsFromPostContent (record-metrics.ts) → platform switch on ps.platform → RecordMetrics object (undefined keys stripped) → attached to the FORENSIC_LOG payload head → sent to service worker for IDB write
10. Comment batch path (index.ts flushBatch) → marker loop: resolve anchor once (resolvedAnchorByPost) → renderTeenMarker per flagged comment (mount='after' for TikTok) → hide-tier: applyCommentHide (hideCommentAsFallbackTerminal, proven before record) → pendingSwaps loop: applyCommentRewriteTerminal (swapCommentTextInPlace + saved-marker re-append + replacementIsVisible) → rememberResolvedComment on a proven outcome
11. content/index.ts → startDiagnostics → sampleHeapNow every 30s → heap MB stored in DiagnosticsSnapshot.samples → schedulePersist → coerceMultiHost + write the opaque content-script session to chrome.storage.local fw_diagnostics. schedulePersist is a 5s debounce, so startDiagnostics also registers a `pagehide` listener calling flushDiagnosticsNow(): without it every counter bumped in a page's last five seconds died with the timer, which silently truncated counters on short visits.
12. interceptor.ts heavy-drain events → bumpCounter('interceptor.batchesDrained') + setGaugePeak('interceptor.pendingNodesPeak') → same session snapshot; readDiagnosticsResult separately selects the worst heap session and sums all retained daily counter sessions
