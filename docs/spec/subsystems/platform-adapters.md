# Subsystem: platform-adapters

> Traced from code. Confirmed defects live in the defect register `known-issues.md`, which is not part of the public copy; [KNOWN-LIMITS.md](../KNOWN-LIMITS.md) carries what a reader outside the project needs from it. Re-read against the code in the 2026-08-23 objective audit (spec-drift.md items 26 to 35).

## Purpose

Turns rendered DOM nodes into PostContent[] records — one record per post, caption, or comment — that the rest of the FeelingWise pipeline consumes for AI classification and forensic-chain recording. Each adapter is responsible for: discovering the correct node set for its platform, extracting text + author + id + engagement metrics, assigning kind/depth/parent_id/parentVideoId for grouping, deduplicating across lazy-load and scroll re-entries, and gating out private-message surfaces and already-processed nodes.

## Inputs

DOM NodeList from interceptor.ts MutationObserver (addedNodes per mutation record); platform discriminated by detectCurrentPlatform() reading window.location.hostname.

## Outputs

PostContent[] to src/content/post-path/dom-interceptor.ts onPostDetected callback, which routes to the comment-batch enqueue path and ultimately to encounter-builder.ts + pipeline.ts. Adapters never write to the page: a rewrite reaches the DOM through src/content/post-path/result-apply.ts, which calls injectIntoElement in src/content/injector.ts.

## Invariants & contracts

- Chain-mirror invariant: extraction reads ONLY rendered DOM at call time — no API resolution, no pre-fetch of un-expanded replies. (twitter.ts, tiktok.ts)
- Per-element dedup: every seen node is stamped with a dataset attribute before any downstream push; lazy-load re-entries skip already-stamped nodes via fwCommentSeen / fwCaptionEmitted / fwProcessed / fwReelProcessed / fwTileSeen. Three bounded exceptions exist, each one shot per element: (1) X late ad-label recheck: a stamped tweetText whose article has no `<time>` and now matches `extractIsXSponsored` is re-extracted exactly once (`fwAdRecheckClaimed`; lock sponsored-detection.test.ts E1); (2) TikTok M70 remount claim: a sponsored root that previously reached a full hide can claim one reprocessing pass after the platform removes that hide state (`tiktok-ad-remount.ts`); (3) TikTok M94 late-marker claim: `rememberTikTokOrganicCaption` at organic emission and `claimTikTokLateAdMarker` at the caption gate let a card whose `ad-tag` hydrated after its caption was emitted re-enter the sponsored gate once, same real id only. (facebook.ts, instagram.ts, tiktok.ts, youtube.ts, twitter.ts)
- Persistent comment ID counter: FB _extractComments reads article.dataset.fwCommentNextIdx at entry and writes it back at exit so chain IDs fb-cmt-${postId}-c${N} are globally unique even across lazy-load re-entries. (facebook.ts)
- parentVideoId cohesion: all comment records from one post share `parentVideoId` = the bare platform id the post record also carries as its own `parentVideoId`; the post record's `id` itself is prefixed on Facebook (`fb-`) and TikTok (`tk-vid-`), so grouping keys on `parentVideoId`, not on `id`. (facebook.ts, instagram.ts, tiktok.ts, youtube.ts)
- Private-message surface exclusion: isPrivateMessageSurface() + findChatOverlayAncestor() block extraction before any DOM read, and isInPrivateChatSubtree() drops any candidate inside a dialog or `role=log` subtree. (adapter.ts)
- 0 is not a lie: engagement counts return undefined rather than 0 when the DOM element is absent — 0 would corrupt amplification-ratio math downstream. (twitter.ts, facebook.ts)
- Sponsor flag is post-only, never comment: is_sponsored set at depth=0 only. (twitter.ts, facebook.ts)

## How it SHOULD work

interceptor.ts fires extractPosts(addedNodes) on every MutationObserver batch. The platform adapter for the current host receives the NodeList, discovers its native post/comment shells (article, recommend-list-item-container, ytd-backstage-post-renderer, etc.), extracts text+author+id+metrics from each unseen node, stamps it seen, and returns PostContent[]. The encounter-builder then combines the per-post and per-comment records into an Encounter for the BATCH classifier. The page-world fetch / XHR interceptor is armed, not installed: nothing reaches parseXPayload in production.

## How it ACTUALLY works

Twitter: extractPosts (twitter.ts) calls _collectTweetNodes per added node, filters truncated tweets (fwTruncatedAt backoff, twitter.ts), calls _extractHandle / _extractStatusIdentity (atomic author + id from one status permalink, required to match the visible handle), then falls back to crypto.randomUUID() when no coherent identity resolves — the seed bug: a tweet with no parseable /status/ link gets a random id, breaking chain cohesion. Permalink tree is walked via walkPermalinkTree (twitter.ts) to assign depth/kind/parent_id; focusedTweetId is computed to set parentVideoId on children-of-focused. buildPermalinkEncounterContext (twitter.ts) is a separate export that re-walks the full document for the encounter assembler at flush time. Metrics come from the aria-label group first (parseTweetGroupAriaLabel, twitter.ts) then per-button spans as fallback. Scroll re-trigger hands un-stamped article elements to the interceptor through requestReExtract (scroll-trigger.ts); it no longer moves any DOM node (twitter.ts, 2026-09-02).

Facebook: extractPosts (facebook.ts) calls _collectArticles which favors [aria-posinset] wrappers over [role=article] (facebook.ts). _extractText (facebook.ts) queries [data-ad-rendering-role=story_message] first; falls through to _extractTextElement (longest dir=auto heuristic). Normal post comments are extracted by _extractComments, which targets [role=article][aria-label] with multi-language COMMENT_LABEL_STEMS and derives depth by walking the ancestor chain. Candidates whose aria-label matches no stem bump fbCommentDroppedLabel, and (2026-08-20) those of them that still carry a body element with 5+ characters ALSO bump fbCommentDroppedLabelWithText: the first counter conflates a correctly-rejected wrapper (shared post, ad) with a real comment in a language the stem list lacks, and the second is the discriminator. The aria-label text is deliberately never recorded — it contains the commenter's name and the diagnostics blob leaves the machine. On `/reel/`, a dedicated branch bypasses the normal article collector, roots at `[role="complementary"]`, emits a reel video record, and calls `_extractComments(comp)` for the side panel (`facebook.ts`); one authenticated current reel yielded six rendered comments, all stamped seen. Caption metrics (extractFacebookPostMetrics) are populated (facebook.ts) — types wired. Post id from _extractPostId (facebook.ts) scans link hrefs for /posts/, /permalink/, story_fbid, /reel/ patterns; returns null if none match, falls to crypto.randomUUID() at facebook.ts. postUrl from _extractPostUrl reads AT MOUNT: in-article permalink anchor → /photo → _derivePostPermalink (builds `<actor>/posts/<id>` from id + the article's own author/group anchor) → /groups/<id>/ container → mount-time location.href; the captured value is stashed on dataset.fwPostUrl and carried to comment records so buildPostUrl (index.ts) never re-reads a post-navigation homepage at log time (M36). Re-entry on lazy-loaded comments uses per-element stamps plus the persistent counter.

Instagram: extractPosts (instagram.ts) collects articles, gates per-caption on fwCaptionEmitted (not article-level fwProcessed). Falls through three surface-specific fallbacks: _extractReelSurface (instagram.ts) for /reels/, _extractPermalinkSurface (instagram.ts) for /p/<id>/, _extractTileGridSurface (instagram.ts) for /explore/ and profile grids. Comments via _walkCommentsContainer (instagram.ts) which delegates to extractCommentRows from dom-master; first li is dropped as caption row. L2 (replies) are not extracted — all emitted comments are depth=1, kind='top-comment' only (instagram.ts). sourceUrl fallback chain: /c/ link href > parent post URL > location.href. Caption sourceUrl comes from _extractPostUrl (instagram.ts): first a[href] whose path contains /p/ or /reel/; relative hrefs are prefixed with https://www.instagram.com, and an absolute href is taken only when isForeignPostUrlHost (content/post-url-host.ts) says its host is Instagram's — facebook.com uses both path shapes, so a foreign anchor is refused, bumps postUrlForeignHostRejected, and the scan continues. Every platform's sourceUrl passes the same host check once more at the buildPostUrl chokepoint (index.ts), which is OBSERVATION ONLY: a disagreement bumps postUrlForeignHost and warns once per platform|page|url-host triple, and the URL is returned unchanged because a wrong URL is still the evidence of what happened. The modal scroll trigger hands caption-stamped articles to the interceptor through requestReExtract (scroll-trigger.ts) and touches no DOM node; the scroller discovery (_findDialogScrollContainer, IG and FB alike) caches a hit per dialog and, since 2026-09-02, also remembers a miss and re-walks a scroller-less dialog at most every 2 s (SCROLLER_PROBE_RETRY_MS), because the getComputedStyle walk over every dialog element used to repeat on every extractPosts call while such a modal stayed open; the previous detach/re-insert of the modal article killed the comment composer's focus every 250 ms scroll debounce and re-armed itself through the scrollTop restore, so it looped every ~258 ms (measured live 2026-09-02, instagram.ts; the Facebook modal pass is the same shape and was changed with it).

TikTok: extractPosts (tiktok.ts) returns [] immediately for tile surfaces (explore/profile/search/hashtag). For feed/permalink calls _buildSplitPosts per container. _buildSplitPosts (tiktok.ts) calls extractTikTokBundle with skipRow=isCommentRowSeen. When snapshot is non-null: emits 1 caption record (kind=video) + N comment records (kind=top-comment, depth=1 only). Caption dedup is normally `fwCaptionEmitted` plus the runtime `emittedVideoIds` set. `tiktok-ad-remount.ts` adds a card-scoped WeakMap for sponsored roots: `injectAdHide` records a successful hide under the strict wrapper id; when that same root and id return sponsored without `data-fw-ad-hidden`, the adapter emits once despite both dedup guards. A successful re-hide rearms the state. A changed or identity-unsafe sponsored rehydration consumes the old state and emits once as a fresh sponsored record without authorizing the recorded wrapper identity. Never-hidden, different-root, and non-sponsored cards cannot claim this path. extractTikTokVideoMetrics (tiktok.ts) reads [data-e2e=like-count/comment-count/share-count] — but these lazy-render; on off-screen containers they return undefined, leaving metrics blank in the chain (seed bug). When snapshot is null (empty caption): falls back to extractCommentsFlat('tiktok', root) from comment-extractors.ts; feed extraction passes the current video container, while permalink extraction passes `document` because its comment panel is a sibling. This prevents a mounted neighbour's first document-level comment list from being stamped with the current video's synthetic parent id. The fallback emits an empty-text video record + comment records. Comment ids are synthetic (synthId=crypto.randomUUID) inside tiktok-bundle.ts; outer record id is tk-cmt-${videoId}-${c.id} (tiktok.ts).

YouTube: extractPosts (youtube.ts) returns [] on /watch path entirely. Only extracts ytd-backstage-post-renderer (community posts). No comment extraction. Post id from /post/ link href; falls to crypto.randomUUID() (youtube.ts). No engagement metrics extracted.

Wire parsers: each of the five platforms has one in wire/ (the FB/IG/TT stubs deleted 2026-07-14 were later replaced by real parsers), and the page-world interceptor that feeds them is installed at page load. The parsers only fill fields on records the DOM adapters make, so the DOM adapters are still the only path that makes a record on every platform.

## Data flow (through this subsystem)

1. MutationObserver addedNodes -> interceptor.ts onMutation -> adapter.extractPosts(nodes: NodeList)
2. nodes.forEach -> adapter._collectTweetNodes / _collectArticles / _collectVideoContainers / _collectContainers (platform-specific node discovery)
3. container/article element -> _extractText / _extractTweetId / extractAuthor / extractVideoId / extractPost (text + id + author extraction from DOM)
4. article -> extractTweetMetrics / extractFacebookPostMetrics / extractTikTokVideoMetrics (engagement metrics from DOM)
5. container -> extractTikTokBundle (tiktok-bundle.ts) -> ThreadSnapshot {post, comments[]} (TikTok only; wraps extractPost + extractComments)
6. extractComments (tiktok-bundle.ts) -> resolveTikTokCommentSearchScope (the card-scoped element tiktok.ts resolvePublicTikTokCommentSearchScope hands over) -> querySelectorAll(TT_COMMENT_ROW_SELECTOR) -> at most DEFAULT_BUNDLE_COMMENT_CAP (15) unseen rows per pass -> extractCommentsFromRowNodes / extractCommentsFromListChildren -> CommentNode[] with surface_order index
7. snapshot / raw article -> _buildSplitPosts (tiktok.ts) -> PostContent[] caption record (kind=video) + PostContent[] comment records (kind=top-comment)
8. PostContent[] -> interceptor.ts onPostDetected -> encounter-builder.ts assembleEncounter / comment-batch enqueue
9. page-world interceptor (installed at page load) -> relay -> the platform's wire parser (on X: parseXPayload -> walkTweetResults -> mapToPostContent) -> PostContent[] -> wire-store.ts rememberWireItem; onPostDetected fills the DOM record's gaps from it (enrichPostFromWire) and the wire never makes a record of its own
10. pipeline.ts neutralize verdict -> post-path/result-apply.ts applyNeutralizedRewriteTerminal -> injector.ts injectIntoElement -> the post's text replaced in place; no adapter method takes part

## Known divergences (Phase-1 flags)

- **[med]** twitter.ts — tweetId = coherent status identity ?? crypto.randomUUID(). When the status link is absent (profile pages with certain article layouts, or the time element fallback fails at STATUS_LINK_SELECTORS[2]), a random UUID replaces the real tweet id. That id still seeds the chain record and the comment-batch bucket key, and chain records for the same tweet across two scroll passes still get different UUIDs (no cross-container dedup equivalent to emittedVideoIds on TikTok). This is the documented seed bug — the id instability is unresolved. (The dashboard 'View original' dead-link symptom of this bug is resolved — see Resolved M1.) — src/content/platforms/twitter.ts
- **[low]** extractTikTokVideoMetrics reads [data-e2e=like-count/comment-count/share-count] from the container once, at caption emission, inside the caption-seal guard (seed bug #2, fixed in 62fd8e3 and live-verified on /foryou with real counts). The metrics are never re-read after `fwCaptionEmitted`, so a card whose action rail hydrates after the seal records blanks: a theoretical partial-render race, the one status surfaces/tiktok.md, surfaces/README.md and known-issues.md now share. — src/content/platforms/tiktok.ts:extractTikTokVideoMetrics

## Resolved

- **M1 — X dead 'View original' link for synthetic-id tweets.** twitter.ts built sourceUrl = x.com/{handle}/status/{tweetId} unconditionally; when tweetId was the crypto.randomUUID() fallback (extraction failed), that /status/<uuid> URL is a guaranteed 404. Fixed: a v4-UUID-shape guard (SYNTHETIC_UUID_RE, twitter.ts) gates the sourceUrl build — a synthetic id leaves sourceUrl empty so the dashboard shows no broken link (buildPostUrl then falls back to the current page URL). The record id is unchanged (the seed-id instability remains a separate divergence). Test: tests/unit/content/platforms/twitter-adapter-encounter.test.ts ('synthetic-UUID tweet id yields no /status URL' — UUID id → no /status/ sourceUrl; real numeric id → /status/<id> sourceUrl). — src/content/platforms/twitter.ts
- **M3 — Facebook random-UUID post id on modern home-feed posts.** _extractPostId returned null for posts whose in-article timestamp href is '#' or '/' at mount time, falling to crypto.randomUUID() at facebook.ts (chain id with no relation to FB's real post id). Fixed: the in-article anchor scan now also matches /share/p/ and /share/v/ permalinks, and a new _extractPostIdFromPath fallback derives a deterministic id from location.pathname (group /posts/ & /permalink/, user /posts/, /share/p|v/, ?story_fbid=) BEFORE the UUID fallback. Restricted to path forms that identify ONE post — a bare feed path still falls to UUID (no cross-post collision). dataset.fwPostId stash unchanged. Test: tests/unit/diagnostics/facebook-adapter.test.ts ('M3' — /share/p/ & /groups/.../posts/ URLs yield deterministic ids; bare home-feed URL still falls to a UUID). — src/content/platforms/facebook.ts
- **M29 — Instagram L2 replies dropped on the article/modal path.** _walkCommentsContainer emitted every direct <li> as depth=1 / kind='top-comment'; a nested reply <ul> rendered under an L1 comment was dropped. Fixed: after each L1 record, a direct-child reply <ul> (`:scope > ul`) is walked by _walkReplyRows, emitting each rendered row as depth=2 / kind='reply' with parent_id = the L1 comment id. Chain-mirror respected — only replies actually rendered/expanded are emitted; nothing is force-expanded. Test: tests/unit/content/platforms/instagram-adapter.test.ts ('M29' — expanded reply ul emits a depth-2 reply tied to its parent; a comment with no nested ul emits only the depth-1 record). — src/content/platforms/instagram.ts
- **M2 — parentVideoId format split (TikTok).** `derivePlatformVideoId` (video-pipeline.ts) returned a `tk-vid-`-prefixed id for TikTok while the adapter (tiktok.ts/598/666/752) and forensic-join.ts stamp BARE digits. The dashboard groups by exact-string `parentVideoId`, so pre-rewrite-hidden TikTok comments split into a separate card. Fixed: the TikTok branch now returns bare digits (m[1]); buildCanonicalPostUrl matches on `/^\d+$/`. The dashboard's stripParentVideoIdPrefix already tolerates bare ids. Test: tests/unit/content/post-path/derive-platform-video-id.test.ts (bare-digit assertions + adapter-format match). — src/content/post-path/video-pipeline.ts
- **M4 — synthetic music/empty-caption id was non-deterministic.** The fallback chain is now in-card `/video/` href, then the strict `xgwrapper-<player>-<19 digits>` id (readTikTokVideoIdFromXgWrapper, M69), then the permalink URL id, then the synthetic id. The synthetic `tk-music-<ts>-<rand>` id was re-minted on every extraction pass, so each scroll over the SAME empty-caption feed container produced a NEW id and its lazy-loaded comments split into a separate chain group. Fixed: synthetic ids are cached per container element in a WeakMap (getSyntheticVideoId). Test: tests/unit/content/platforms/tiktok-adapter.test.ts ('reuses the same synthetic parentVideoId across two extractions of the same container'). — src/content/platforms/tiktok.ts:getSyntheticVideoId
- **LOW — duplicate SPA-nav listeners.** video-pipeline.ts registered yt-navigate-finish/popstate twice (setupNavigationListeners + an inline block in initVideoPipeline), firing onNavigate twice per navigation. Fixed: setupNavigationListeners now takes the single nav handler; the inline duplicate registration + its cleanup were removed. The URL-poll path now also re-arms the comment fallback poll (previously only popstate/yt-navigate-finish did). — src/content/post-path/video-pipeline.ts:setupNavigationListeners,initVideoPipeline
