# Subsystem: storage-license

> Traced from code. Confirmed defects live in the defect register `known-issues.md`, which is not part of the public copy; [KNOWN-LIMITS.md](../KNOWN-LIMITS.md) carries what a reader outside the project needs from it. Re-read against the code in the 2026-08-23 objective audit (spec-drift.md items 102, 103).

## Purpose

Manages all persistent state for the FeelingWise extension: user settings (FWSettings shape + versioned migrations), license tier resolution and cap arithmetic, a three-tier verdict cache (L1 in-memory / L2 chrome.storage.session / L3 chrome.storage.local), developer feature flags, mode presets (child/teen/adult default feature grids), and the AI-content blocklist defaults. Together these provide the single source of truth that the pipeline, content scripts, UI surfaces, and forensic chain consult before every decision.

## Inputs

On read: chrome.storage.local raw key-value blob keyed by the SETTINGS_KEYS array (settings.ts; 30 entries). License key stored under 'fw_license_key' (license.ts). Feature flags stored under 'ff_<name>' prefix (feature-flags.ts). Cache reads from chrome.storage.session (L2) and chrome.storage.local (L3). Pipeline calls getSettings() + getLicense() at every post-processing entry (pipeline.ts:process). Client.ts calls getLicense() + getSettings() before each AI call (client.ts:callAI).

## Outputs

FWSettings object to: pipeline.ts (cap enforcement, feature gating), client.ts (daily cap check), ai/client.ts (bearer token construction from license), content scripts (feature toggle reads via isFeatureEnabled), UI surfaces (popup, dashboard, SettingsSurface.tsx). LicenseInfo to: pipeline.ts, client.ts, orchestrator.ts. processingCache verdicts to: pipeline.ts (dedup short-circuit). FeatureFlags to: content/index.ts (`batchRewriteEnabled` in flushBatch, `chainDebugStats` gating the GET_CHAIN_DEBUG_STATS request), core/neutralizer.ts (`capturePromptIO`), core/perf-trace.ts (`captureV2Metrics`), content/queue.ts (`captureBehavior`), content/metrics-probe.ts (`metricsScopeProbe`), content/yt-watch-comments.ts (`ytWatchComments`: YouTube /watch capture gate, default TRUE since 2026-08-02; an explicit stored false is the kill switch). pipeline.ts imports the flag reader but never calls it, and no `useCategoryAxes` flag exists.

## Invariants & contracts

- License changes reach the popup without a reload (2026-08-11): the popup's cross-surface RELOAD_ON list (Popup.tsx) carries `fw_license_key` so the tier pill and caps refresh live. The two media start-gate listeners in content/index.ts that rebound on the key, and their lock tests/unit/license-rebind.test.ts, left the build with the media signals in 2.5.0; content/index.ts no longer reads the key. The 2026-08-11 sweep family is fully resolved: the popup monthly share + pause lines read the cap markers, and the popup Home tab's daily-cap formula matches the enforcing gate's dailyCap<=0 sentinel handling (lock: popup-monthly-honesty.test.ts; the License tab's formula still does not, known-issues M117). The same day closed the other two: the AI-call meter (now recordAiCall) is serialized through the counter-write chain (lock: counter-serialization.test.ts), and hasStoredPaidLicenseKey is tri-state ('present'/'absent'/'unreadable') so a storage blip is never reported as genuine free tier.
- Text-path proxy-cap latch (2026-08-11): the first cap_daily/cap_monthly 429 arms an in-memory latch in callAI that short-circuits before the network until the UTC period rolls, re-armed from the `textCapReached` storage marker once per realm; the dashboard Issues tab renders the period-scoped pause card. Gate order unchanged: master-off, tier-free, client daily cap, then the latch. Lock: tests/unit/ai/text-cap-latch.test.ts. The latch and the marker carry `licenseFingerprint` (storage/cap-markers.ts: tier plus the last four secret characters); callAI drops a latch whose fingerprint is not the current key's, and setLicense/clearLicense remove both `textCapReached` and `mediaMonthlyCapReached`, so a trial key's cap never binds a freshly pasted paid key. Markers written before the fingerprint existed carry none and are honoured as before.
- Single counter writer (STORAGE-LICENCE-WORKER-7, 9): a realm with a `document` (content script, popup, dashboard) never writes a usage counter itself; `recordAiCall`/`incrementNeutralized`/`incrementMetricsHidden` send `USAGE_INCREMENT`; when the worker does not ack the increment is lost and the loss is logged once per reason (the promise resolves, because most callers are `void` on a paint path where a rejection is only an uncaught-promise line). The worker's `applyUsageIncrement` runs the serialised read-modify-write and, when its cached snapshot's `lastResetDate`/`lastResetMonth` are behind the clock, drops the cache and re-reads before computing the write (the fresh read runs the reset block), so a rollover never carries the previous period's count. A realm with no `document` and no runtime messaging (a node test host) applies locally through the same function. Lock: tests/unit/storage/usage-counter-single-writer.test.ts, tests/unit/storage/counter-write-serialisation.test.ts, tests/unit/storage/counter-serialization.test.ts.
- One metering table on both sides (STORAGE-LICENCE-WORKER-3): `src/storage/usage-weights.ts` and `worker/src/usage-weights.ts` are byte-identical (lock: tests/unit/usage-weights-parity.test.ts) and carry the $0.10/M counter basis and the chat prompt/completion rates, with `chatTokenEquivalents`. The proxy meters through them; so does `src/ai/client.ts`, calling `recordAiCall` on a 2xx. (The media weights went with the media features in 2.5.0.) `totalTokensThisMonth` is therefore in token-equivalents, so the popup's monthly share (`Popup.tsx`, `totalTokensThisMonth / effectiveMonthlyTokenCap`) divides the same quantity the proxy caps; `totalTokensToday`/`totalTokensAllTime` stay raw tokens.
- Fail-closed on storage error: getSettings() returns child mode + childPreset() when storage throws AND no cached snapshot exists (settings.ts:getSettings).
- getSettings fast path: a 5 s TTL cache (`SETTINGS_CACHE_TTL_MS`) returns the SAME object reference while fresh, so two reads inside the window are identical; the cache is invalidated by every saveSettings / updateFeature write and by the storage listener; when `isContextAlive()` is false the read short-circuits to the cached or fail-closed snapshot without touching storage.
- Daily cap enforced at two independent gates: pipeline.ts:process (pre-LLM, `settings.dailyCap > 0 ? min(settings.dailyCap, tierCap) : tierCap`) and client.ts:callAI (settings.dailyCap alone, no tierCap min). Neither gate fires for isUncappedTier(tier) === true.
- Monthly token cap enforced in pipeline.ts:process via effectiveMonthlyTokenCap(tier, monthlyUsdCapOverride). `effectiveMonthlyUsdCap` returns any finite non-negative override, above or below the tier cap (no min against the tier ceiling; the settings.ts docblock says the parent may dial higher); the worker enforces its own $3.50 independently, so a higher client override only moves the client's local pause point.
- Free tier (`tierCap === 0`) always returns passWith('pre-llm-free-tier-no-ai') in pipeline.ts:process — zero LLM cost regardless of any other setting.
- Cache key MUST include platform+mode+locale+outputLanguage dimensions to prevent cross-mode/cross-language verdict bleed (cache-key.ts verdictCacheKeyInput, consumed by pipeline.ts and the comment-batch reframe primer).
- L3 cache entries are version-stamped with chrome.runtime.getManifest().version (cache.ts); a version mismatch = miss, preventing stale verdicts from prior prompt/model versions surviving a release.
- License key regex rejects 'fw-free-*' keys (license.ts LICENSE_KEY_REGEX) so a typed free-key cannot trigger a false 'valid key' confirmation.
- A transient storage read NEVER downgrades a paid/dev user. `lastGoodPaidLicense` (in-memory, per realm) is set only by a successful paid read or `setLicense`, and nulled only by `clearLicense()` or a successful FREE read of a stored value. Both failure shapes consult it: a THROWN read (catch branch) and a RESOLVED-but-empty read (non-string branch) return the cached paid license when it is non-null and leave it armed; only a cold cache (no paid read yet this realm) resolves to FREE. Because every legitimate transition to free routes through `clearLicense()` (nulls the cache) or a fresh install (cache already null), a non-null cache at a failed read is provably a transient blip. — src/storage/license.ts getLicense.
- Free-path latency gate: `getLicense` runs per post, so a genuine free user must not pay the empty-read retry every call. A module-level `realmConfirmedFree` (default false) is set true only when a COLD read (no cached paid license) resolves empty past the retry — i.e. authoritatively free. While true, the empty-read retry is skipped (a single fast read still runs, so a paid key later written by another surface is still picked up; a THROWN blip is still retried). It is reset false whenever a paid key is read or stored (`setLicense`), and set true by `clearLicense` (explicit sign-out — nothing to recover). A `chrome.storage.onChanged` listener in license.ts applies the same transitions when ANOTHER realm removes or replaces `fw_license_key` (removal nulls the cache and confirms free; a new paid key warms the cache), so a popup sign-out reaches every open social tab without a reload. Lock: tests/unit/storage/license-cache.test.ts. This never weakens the invariant above: a confirmed paid license (warm cache) still returns cached on any empty/failed read, and a throw never confirms free. — src/storage/license.ts getLicense/setLicense/clearLicense.
- coerceLegacyMode (settings.ts) returns 'child', 'teen' and 'adult' unchanged and maps only an unknown value to 'teen'; the v2 to v3 migration applies the adult preset for an adult install. presetForMode handles all three modes.
- Parent PIN: `setPin` stores `pbkdf2$<iterations>$<saltHex>$<digestHex>` (per-install random salt, PBKDF2_ITERATIONS shared with key-wrap.ts), `verifyPin` compares in constant time and rewrites a legacy bare SHA-256 digest salted on the next success. An attempt throttle (PIN_FREE_ATTEMPTS 5 free misses, then PIN_LOCK_BASE_MS 30 s doubling to PIN_LOCK_MAX_MS 15 min, state in chrome.storage.local `fw_pin_attempts`, `pinLockRemainingMs` for the UI) fails CLOSED when its state cannot be read. A correct entry stores `pinVerifiedAt` in chrome.storage.session; `isPinGraceActive()` (PIN_GRACE_MS 15 min) lets the popup re-enter Settings without the overlay, while leaving Child, chain reset and restore always demand the PIN. A recovery phrase and a Change PIN row exist (c707ab2). `getSettingsForAttestation()` is the read seam every chain-marker writer uses (reset, rotation, prune, manual flag) so a storage outage is attested as such rather than as a real child setting (raw getSettings is banned in chain writers; lock tests/unit/storage/attestation-seam.test.ts).
- The Child media-capture consent fence (M81, 2026-07-24) is gone with the capture it fenced: the media features were removed in 2.5.0, so `saveSettings` no longer rewrites any partial and `enforceChildMediaCaptureOff` no longer exists.

- Master AI breaker (2026-08-10): FWSettings.aiAnalysisEnabled (additive scalar, DEFAULTS true, no schema bump). false = zero external AI calls: checked first in callAI (src/ai/client.ts, returns cap-exhausted/master-off) and at both media start gates in content/index.ts, which also rebind on its storage change like a mode change. The popup Home tab carries the master toggle (`saveSettings({aiAnalysisEnabled})`, with an off note on every AI feature row). Test lock: tests/unit/storage/client-master-breaker.test.ts.

## How it SHOULD work

On first read: getSettings() loads raw chrome.storage.local, merges over DEFAULTS, runs migrateSettings() chain (v0→v12), handles daily/monthly UTC resets, fills missing feature IDs from preset defaults, caches in _settingsCache. License is resolved once per pipeline entry: parseLicenseKey(stored) or FREE_LICENSE. Cap enforcement: pipeline checks min(settings.dailyCap, tierCap) for daily calls and effectiveMonthlyTokenCap for monthly tokens before any AI call. Client.ts has an additional daily-cap check (redundant safety). Verdict cache short-circuits identical content (platform+mode+locale+outputLanguage+text hash) across L1→L2→L3. Feature flags are developer-only, not user-facing, TTL-cached 5s. Presets seed defaults only; parent toggle changes persist independently of mode tag changes.

## How it ACTUALLY works

getSettings() (settings.ts): reads chrome.storage.local → spreads over DEFAULTS → runs migrateSettings() → writes migration result back to storage for 5 specific keys only (settingsSchemaVersion, features, presets, estimatedCostToday, estimatedCostAllTime — NOT monthlyUsdCapOverride, outputLanguage, dashboardTheme, etc.), and on the v13→v14 hop also REMOVES the orphaned videoUnderstanding/imageUnderstanding keys → checks UTC day reset → checks UTC month reset → fills missing feature IDs from presetForMode → sets _settingsCache → returns. On error: console.error names the error, then returns _settingsCache if available, else the synthetic fail-closed snapshot {DEFAULTS, mode:'child', features:childPreset(), readFailedFallback:true} — the non-persisted `readFailedFallback` marker (D3, 2026-08-04) is set ONLY on this synthetic construction (all three fail-closed paths), never on cached or real reads, and forensic emit sites thread it into `configSnapshot.settingsReadFailed` so records written in the window do not attest a real child install.

pipeline.ts cap path (pipeline.ts:process): getLicense() → dailyCapForTier(tier) → if not uncapped: effectiveCap = settings.dailyCap > 0 ? min(settings.dailyCap, tierCap) : tierCap → check totalChecksToday >= effectiveCap → then check totalTokensThisMonth >= effectiveMonthlyTokenCap(tier, monthlyUsdCapOverride).

client.ts cap path (client.ts:callAI): independent check — if not uncapped AND settings.dailyCap > 0 AND totalChecksToday >= settings.dailyCap → Err cap-exhausted. No tierCap min here; only settings.dailyCap binds.

recordAiCall (settings.ts): one write per successful call: totalChecksToday/ThisMonth/AllTime +1, totalTokensThisMonth + tokenEquivalents (the proxy weighting), totalTokensToday/AllTime + raw tokens, estimatedCost + tokenEquivalents at GROQ_BLENDED_RATE_PER_1M_USD (each direction at the answering model's rate, via meteredTokenEquivalents). Accumulates raw float (no per-call rounding).

processingCache.set (cache.ts): writes L1 (LRU evict at 5000) → fires-and-forgets L2 write → fires-and-forgets L3 write with version stamp → 2% chance triggers sweepL3(). getPersistent: L1 hit → return; L2 check → if expired remove + fall to getL3(); L2 hit → hydrate L1; L3 hit → hydrate L1+L2 with refreshed timestamp.

migrateSettings (settings.ts): sequential if-chain from v0 to v14, no switch-fallthrough. v8→v9 is a no-op schema bump (BYOK removed). v9→v10 backfills dashboardTheme. v10→v11 is a stamp-only bump (it once carried the M81 media-capture fence). v11→v12 is a stamp-only bump that drops videoControls from the shape. v12→v13 backfills the five surface switches. v13→v14 is a stamp-only bump that drops the removed media-understanding flags; getSettings deletes their storage keys on the same write. Each branch sets didMigrate=true and bumps settingsSchemaVersion.

## Data flow (through this subsystem)

1. chrome.storage.local raw blob -> getSettings() merge over DEFAULTS -> migrateSettings(settings) transform -> if didMigrate: persist 5 keys back to storage (settingsSchemaVersion, features, presets, estimatedCostToday, estimatedCostAllTime) and, on the v13→v14 hop, remove videoUnderstanding/imageUnderstanding -> UTC day reset check + write -> UTC month reset check + write -> fill missing feature IDs from presetForMode -> _settingsCache = settings (5 s TTL) -> return FWSettings
2. FWSettings -> pipeline.ts cap check: getLicense() -> dailyCapForTier(tier) -> if tierCap === 0: passWith -> if capped: settings.dailyCap > 0 ? min(settings.dailyCap, tierCap) : tierCap -> if exceeded: passWith('cap-exhausted') -> effectiveMonthlyTokenCap(tier, override) -> if exceeded: passWith -> proceed to AI call
3. post text -> cache-key.ts verdictCacheKeyInput (platform|mode|locale|outputLanguage|text) -> SHA-256 hash -> processingCache.getPersistent(hash) -> L1 get -> L2 chrome.storage.session get -> L3 chrome.storage.local get -> CacheEntry | null returned to pipeline
4. AI call result -> processingCache.set(hash, analysis, neutralizedText) -> L1 LRU insert -> L2 fire-and-forget session write -> L3 fire-and-forget local write with version stamp -> 2% chance sweepL3()
5. AI response (client.ts with chatTokenEquivalents) -> recordAiCall({inputTokens, outputTokens, tokenEquivalents, provider, model}) (settings.ts) -> USAGE_INCREMENT {kind:'ai-call'} to the service worker -> applyUsageIncrement: settingsForCounterWrite (re-read when the period keys are stale) -> one chrome.storage.local.set of totalChecks* (+1), totalTokensThisMonth (+tokenEquivalents), totalTokensToday/AllTime (+raw), estimatedCostToday/AllTime -> {ok:true} ack
6. raw license key string -> getLocalWithRetry(STORAGE_KEY, …, isPresent = STORAGE_KEY in record) (local-read.ts; absorbs transient blips — retries a thrown rejection AND, via the opt-in isPresent predicate, a resolved-but-missing key) -> parseLicenseKey(raw) (license.ts) -> LICENSE_KEY_REGEX.exec(trimmed.toLowerCase()) -> LicenseInfo{tier, secret} | null -> getLicense() returns info or FREE_LICENSE. Two failure shapes both consult the lastGoodPaidLicense net: a read that THROWS past every retry warn-logs then returns lastGoodPaidLicense ?? FREE (catch branch); a read that RESOLVES with no key (empty read past every retry) returns lastGoodPaidLicense when warm (transient blip, cache left armed) or FREE when cold — it no longer nulls the cache (license.ts).

## Known divergences (Phase-1 flags)

- **[low]** client.ts daily cap check does NOT apply the min(settings.dailyCap, tierCap) formula — it only checks settings.dailyCap alone. A user with settings.dailyCap=0 (legacy 'no cap' sentinel) gets NO daily-cap enforcement at the client.ts gate; only the pipeline.ts gate catches it. Two gates with different formulas for the same cap (known-issues Theme C residual). — src/ai/client.ts:callAI vs src/analysis/pipeline.ts:process
- **[RESOLVED]** coerceLegacyMode preserves all three modes; only unknown values fall to 'teen' (src/storage/settings.ts:coerceLegacyMode)
- **[low]** migrateSettings() write-back persists 5 keys (settingsSchemaVersion, features, presets, estimatedCostToday, estimatedCostAllTime). Fields added by v6→v7 (monthlyUsdCapOverride), v7→v8 (outputLanguage), v9→v10 (dashboardTheme) are NOT persisted on migration write-back; the branch does not re-fire because settingsSchemaVersion WAS written, and the field default is ALSO in DEFAULTS, so it loads correctly on the next read anyway. Low real risk. — src/storage/settings.ts:migrateSettings
- **[RESOLVED — 2026-08-23]** ~~trackTokenUsage fallback rate is 0.20/1M while GROQ_BLENDED_RATE_PER_1M in license.ts is 0.10/1M.~~ An unknown model (and every media call) now bills its token-equivalents at the shared counter basis (src/storage/usage-weights.ts), the same figure the proxy charges against the cap.
- **[low]** License key regex is case-insensitive on read but the VALID_TIERS guard after parse checks the already-lowercased match[1]. Since the regex lowercases via /i flag + parseLicenseKey lowercases input, the VALID_TIERS check is redundant but harmless. — src/storage/license.ts:parseLicenseKey
- **[RESOLVED — M24]** getLicense() catch returned FREE_LICENSE on ANY storage error with no log, so a thrown chrome.storage read (paid user's tier read failing → AI silently off) was indistinguishable from the expected fresh/free path. getLicense now only wraps the chrome.storage.local.get in try/catch: a THROWN read error is console.warn-logged ("getLicense storage read failed") then falls back to FREE; a missing/non-string/malformed value still returns FREE silently (expected fresh/free install). Still fails closed. — src/storage/license.ts:getLicense
- **[RESOLVED — M25]** getSettings() outer catch suppressed all errors with no log while failing closed to Child mode. The catch now names the error as its first line (console.error "getSettings read failed — failing closed") so a persistent storage failure that keeps forcing Child mode is no longer invisible. Fail-closed behavior unchanged (prior cache, else Child + childPreset). — src/storage/settings.ts:getSettings
- **[RESOLVED — M27]** A SINGLE transient `chrome.storage.local.get` rejection (observed under the heavy concurrent video/audio I/O of the eyes+ears pipeline) flipped a paid/dev user to FREE on a freshly-injected content script, because the `lastGoodPaidLicense` cache is cold on the first read. Symptom: comment-batch logs `cap=tier-free` even on the uncapped dev tier. getLicense() now reads the license key via `getLocalWithRetry` (src/storage/local-read.ts — 3 attempts, 50ms·n backoff, a dead-context error rethrows immediately without retry), so a momentary blip is absorbed before any FREE fallback. The cold-all-retries-fail edge still falls back to FREE (then warn-logs) — a durable storage-mirror of the last-good tier is the next lever if it recurs. — src/storage/license.ts, src/storage/local-read.ts. Tests: tests/unit/storage/local-read.test.ts, tests/unit/storage/license.test.ts.
- **[RESOLVED — 2026-08-01, empty-resolve hole]** M27 fixed the THROWN-read path but left a second, more severe hole in the same class: a `chrome.storage.local.get` that RESOLVED without throwing yet carried no `fw_license_key` (empty/partial record). The old non-string branch returned FREE **and** nulled `lastGoodPaidLicense`, so this non-throwing path both mis-downgraded a warm paid/dev user AND disarmed the safety net for every later call. Fix: the empty-resolve branch now returns the cached paid license when the cache is warm and only returns FREE (cache left null) when cold; `getLocalWithRetry` gained an opt-in `isPresent` predicate so `getLicense` retries a resolved-but-missing key like a thrown blip, while other callers keep resolve-once semantics and a genuinely-absent key never becomes an error. Genuine-free paths unchanged (fresh install, post-clearLicense). — src/storage/license.ts getLicense, src/storage/local-read.ts getLocalWithRetry. Tests: tests/unit/storage/license-cache.test.ts (warm empty-resolve; cold throw-then-recover), tests/unit/storage/local-read.test.ts (empty-read retry + soft-fail), tests/unit/storage/license.test.ts.
