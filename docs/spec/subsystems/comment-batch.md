# Subsystem: comment-batch

> Traced from code. Re-read against the code in the 2026-08-23 objective audit (spec-drift.md items 58 to 66). The content/ module lines under Key files follow the content/index.ts split and are maintained with it.

## Purpose

Scores a batch of social-media comments in a single LLM call (openai/gpt-oss-20b via the FW proxy; switched 2026-06-18 from llama-3.1-8b-instant), producing per-comment technique/sentiment/severity verdicts and an aggregate room label. Applies deterministic pre-LLM enrichment (harm-floor, emoji-pile, repetition signals) and post-LLM override gates (identity-slur, profanity-tier, coded-harm, rage-format, ad-hominem, RULE 13/14) to compensate for instruction-following gaps measured on the judge model. Also validates any inline or fallback rewrites against the ten-guard `validateRewrite` stack (comment-rewriter.ts) before applying them to the DOM.

## Inputs

Encounter object (`src/types/post.ts`) constructed by `buildEncounterForFlushBatch` from per-platform adapter output — post text, author, metrics, per-comment author/text/metrics/depth/domRef, platform, surface, and output language. X permalink adds rendered ancestry; TikTok, Instagram, YouTube, and Facebook have dedicated rich assembly without ancestry. Missing or unrecognized platform/surface signals, and legacy callers, use `encounterFromLegacyBatchInput`, which synthesizes a degraded form.

Parent observations seed a bounded identity cache keyed by `platform:parentId`. This includes normal post/video records and an X focused reply with no `parentVideoId` when that tweet is the parent of visible child replies. The cache retains only caption, parent URL, and parent author across successive flushes. A later comment always contributes its current platform, feed source, and page permalink; those observation-specific values are never reused. A later exact link for the same parent may replace a generic feed/surface URL, while exact conflicting links remain blocked.

## Outputs

BatchScoreResult (comment-batch-scorer.ts) returned to flushBatch (content/index.ts): per-comment BatchCommentVerdict[] (technique, sentiment, severity 0-10, action, neutralizedText, overrideOrigin), BatchEnvironment (room label, pct breakdown, toxicityScore, slurPrevalencePct, authorRecidivism, discourseQuality, algorithmicAmplification, forensicNarrative), commentHarmFloors[], truncatedIndices[], failed flag, failureKind. flushBatch routes each verdict to FORENSIC_LOG (isManipulative=true) or PASS_LOG (false) or CANCEL_LOG (truncated/failed), applies hide-tier comments through one exact-identity terminal, collects text swaps in pendingSwaps, and optionally runs a second scoreRoom call returning RoomAnalysis merged into the ENVIRONMENT_LOG chain record. Since 2026-08-10 (wiring Q3) scoreRoom is gated on the `comments-to-analyze-per-video` feature toggle (on in every preset; the room read previously had no parent-visible switch) and, like every AI call, on the aiAnalysisEnabled master breaker inside callAI. Lock: tests/unit/content/comment-batch/room-sensor-gate.source.test.ts.

## Invariants & contracts

- Caption context reaches the Encounter (2026-08-11): bucket.posts holds comments only, so the assemblers' in-bucket caption lookup never matched. The chokepoint captures caption/post records (bounded map keyed like the room context) and the flush hands them plus bucket.videoAuthor to buildEncounterForFlushBatch as CaptionContext; assemblers fall back to it for is_sponsored, author, and FB caption metrics. Without context the blank behavior remains (no invention). Lock: tests/unit/content/record/encounter-caption-context.test.ts.

- Fail-closed on every LLM failure path. Eight call sites in scoreBatch route to failClosed: zero children; the non-Latin script gate; the prompt-builder throw; the circuit-breaker hold; a cap-exhausted / non-ok callAI result; a thrown callAI; an unparseable reply with nothing salvageable (failureKind='provider-unparseable-json'); and a parsed reply with no usable comments array (failureKind='provider-empty-verdicts'). Those last two carried NO failureKind before 2026-09-02, so the console guessed one name for both and the Operational Events panel counted them as 'network'. failClosed still applies identity-slur escalation, coded-harm detection and the HF>=70 floor deterministically. VISION §1.2.
- Chain-mirror gate (content/index.ts flushBatch): scoreBatch is skipped entirely when neither comment-rewrite nor markers are enabled for the platform — no LLM call, no chain record. Prevents phantom records for content the child did not observe.
- Viewport gate (content/index.ts flushBatch, filterToViewed): only comments whose DOM element crossed the viewport are flushed through scoreBatch. Unviewed posts are un-stamped for re-extraction.
- MANIPULATION_SEVERITY_THRESHOLD = 6 is the single shared constant for the flag boundary; imported by content/index.ts and corpus harnesses — cannot drift.
- isManipulative is the single shared flag predicate: action==='hide' OR (severity >= 6 AND technique NOT in NON_MANIPULATION_TECHNIQUES). Both content/index.ts and harnesses import the same function.
- overrideOrigin field is stamped on every verdict the deterministic gate mutates; forensic record carries it so the chain never implies AI diagnosis when a regex override fired.
- Batch LRU cache: only non-failed results are cached; cache key includes mode + platform + output_language to prevent mode-switch or language-toggle returning stale verdicts. Cache is cleared on chain reset via clearBatchCache.
- target_present gate: shame-attack with target_present===false is downgraded to genuine-opinion sev<=3 before override gates run. The model does not fill the field (the gate fired 0 times across both 2026-07-24 baselines), so since 2026-08-02 an OMITTED/non-true field falls through to a code-side presence check (hasPresentTarget: @-mention or second-person address, EN+RO, overmatching). Dehumanizing text and scapegoating are never downgraded. This reaches the FLAG tier, reversing the 2026-07-24 hide-only boundary; the boundary's own rationale was scapegoating true-positive loss, which is untouched. Locked by tests/unit/analysis/present-target-hide-exemption.test.ts.
- applyOverrideGates gate order is load-bearing (comment-batch-scorer.ts:applyOverrideGates), seven gates: identity-slur -> child profanity floor -> profanity-tier-hide (sev>=8) -> coded-harm -> rage-format -> HF>=70 -> ad-hominem. Each gate returns immediately on fire; severity is always Math.max (never downgrades an already-higher LLM verdict).
- validateRewrite ten-guard stack (comment-rewriter.ts:validateRewrite): too-short / meta-talk / false-self-admission / advisory-injection / length-blowup / register-flatten / forbidden-meta / profanity-preserved / near-identical / language-drift. Applied to BOTH inline BATCH V3 rewrites AND neutralizeText fallback rewrites (content/index.ts flushBatch rewrite pass).
- Hide-on-rewrite-unavailable: `isUnrewritable` in the rewrite pass is `isDehumanizing || isHarmLaundered || (!rewrite && (identitySlurMatch || (sev >= 7 && (shame-attack not absent-target-exempt | scapegoating | anger-trigger | fear-appeal)) || hideOnRewriteUnavailable(mode, strictLanguage, hideUnrewritable)))`. The last disjunct (core/pipeline.ts, shared with the post path) is true in Child, under strict language, or with the hide-unrewritable toggle: in those states EVERY confirmed flag whose rewrite came back empty or rejected hides, the allowlist and the absent-target exemption notwithstanding. Only Teen / Adult with both toggles off keep the four-technique allowlist (known-issues M49).
- Non-Latin script gate (comment-batch-scorer.ts:isNonSupportedScript): combined post+comments text with ≥50 non-Latin chars and non-Latin count ≥3× Latin count skips the LLM call, routes to failClosed with failureKind='pre-llm-unsupported-language'. Harm-floor + slur escalation still fires in failClosed.
- Comment-room identity cache (`content/comment-batch/queue.ts`): at most 500 entries, keyed by platform + parent id. Parent-only detections do not create timerless `pendingBatches`. When comments are already pending, real author/URL conflicts cannot replace the first observed room; default fields may still be filled, and a generic surface URL may be promoted to an exact URL that targets the same parent. Route cleanup clears both pending batches and remembered identity.
- Forensic dedup gates (`content/forensic-gate.ts`: shouldLogForensic / hasLoggedForensic / shouldLogCancelForensic) key on comment text alone; every record branch in flushBatch depends on them. A second comment with identical text but another author or id is skipped at the record level, and since 636f83e the prior verdict is re-applied to the skipped node (cover, hide or rewrite) so protection does not depend on the record (known-issues M106).
- Comment HIDE outcome (`content/index.ts`, `dom-recycle-recovery.ts`, `comment-overlay.ts`): the DOM target is revalidated before mutation. Facebook recovery is limited to one parent-post scope and one unique exact full-text + depth match, plus author when available. The record receives `action:'hide'` only after `data-fw-hidden-fallback` and `display:none!important` are present; a miss records `action:'mark'`, and Child mode retains the provisional cover. No document-wide text fallback or timed retry exists.

## How it SHOULD work

On each batch flush, the system should: (1) enrich comments with deterministic harm-floor signals; (2) build a rich prompt (POST_ENVIRONMENT + ANCESTRY + per-comment lines with HF flags + emoji cluster) and call the LLM once for all comments in a batch (up to 5 per batch, `COMMENT_BATCH_MAX_SIZE`, chosen against lost-in-the-middle; a 1,500 ms debounce and an 800 ms per-parent floor in comment-batch/queue.ts); (3) parse the structured JSON response; (4) apply code-side override gates for cases the judge model misses; (5) compute room-level aggregates deterministically from per-comment verdicts; (6) run a separate second LLM call (scoreRoom) in parallel for the room-analysis narrative; (7) for flagged comments, use the inline rewrite from the BATCH response directly, falling back to a per-comment neutralizeText call; (8) validate all rewrites through the ten-guard stack; (9) write forensic chain records (FORENSIC_LOG/PASS_LOG/CANCEL_LOG) and apply DOM mutations (text swap or hide).

## How it ACTUALLY works

Traced at each hop:

0. `onPostDetected` seeds parent identity before any session-verdict/pass/hide fast path can return. It treats an X focused reply without `parentVideoId` as a parent observation. The seed updates a populated pending batch only through the guarded room merge; with no comments pending it updates only the bounded identity cache.

0a. A successful non-manipulative comment verdict enters the same bounded, exact-input session PASS cache used by posts. Before a later batched-comment cover or enqueue, `routeBatchedComment` checks the key built from id, platform, author, kind, parent identity, depth, text, and extracted context. An exact return bypasses both the Child cover and batch queue. A second fast path, `sessionCommentResolutionByKey` (content/late-verdict-cache.ts; proven hides and validated rewrites, written by `rememberResolvedComment`), triggers `reapplyResolvedComment` on the fresh node: it mounts the cover, re-swaps or re-hides the node, and keeps the cover when neither lands (lock: tests/unit/content/comment-resolution-cache.test.ts). Batched comments never enter the `ProcessingQueue` at all: `onPostDetected` routes them straight to `enqueueCommentForBatch`. Changed text or room identity takes the normal first-protection path. Failed, truncated, cap-exhausted, profane-soften, and acted-on outcomes do not enter this PASS cache.

0b. Runtime `strictLanguage` (and `hideUnrewritable` / `features`) changes invalidate the same classification generation as a mode change, clear every session verdict cache and pending comment batch, remove every teen marker when `show-reframe-markers` is off for the platform, and rescan the current surface. This prevents an exact PASS recorded while strict language was off from bypassing the newly enabled profanity-soften policy. Other storage changes do not trigger this reset.

1. `enqueueCommentForBatch` checks `isParentInCooldown` (a parent whose last flush failed sits out `setParentCooldown`'s window) and creates a pending batch from the platform-scoped remembered identity when available, while stamping `feedSource`, `platform`, and `permalinkUrl` from the current comment observation. At drain, `takePendingBatchForFlush` applies the id-gated fallback once and freezes one room snapshot. `commentRecordRoomFields` threads that same `postUrl` / `roomAuthor` / `roomCaption` / `roomUrl` into successful, fail-closed escalation, fail-closed cancellation, and truncated-cancellation comment records; `ENVIRONMENT_LOG` consumes the same prepared room. `buildEncounterForFlushBatch` then walks X-permalink ancestry or selects the dedicated TikTok, Instagram, YouTube, or Facebook assembler; incomplete/unrecognized observations use the degraded legacy bridge.
   If `buildEncounterForFlushBatch` or `scoreBatch` throws, the catch unmarks the bucket for re-extraction, keeps every Child cover (protectionsToRetain) and writes one `cancelled-batch-llm-failure` CANCEL_LOG per comment with `failureKind: 'internal-error'`; it never uncovers the bucket silently. Lock: tests/unit/content/comment-batch/comment-hide-terminal-wiring.source.test.ts.
   The flush's `finally` and the proven-rewrite branch settle every comment not in protectionsToRetain through `settleProtection` with record `batch` (src/content/protection/settle-protection.ts); no comment path calls `releaseProtection` directly. The cap-exhausted and truncated-slot paths still reach that finally without a record of their own, which is the open PROTECTION-PATH-6 decision.

2. comment-batch-scorer.ts cache key check (`cachedBatchResult`). Hit → return immediately, skip all processing.

3. comment-batch-scorer.ts `enrichWithHarmFloor`: for each child, runs `computeHarmFloor` (harm-floor.ts, categories A/B/C/D/E/I regex only, no L1 techniques), `filterProfanity` for identity-slur check, `detectEmojiPile`, `detectRepetition` (pre-llm-signals.ts). Scores composite = min(100, hfScore + slurBonus(50) + emojiWeight + repetitionWeight). Stamps harm_floor on each child in an Encounter copy (pure function). Comments with totalScore=0 get no stamp.

4. comment-batch-scorer.ts `isNonSupportedScript` check. If dominantly non-Latin → failClosed immediately. Harm-floor/slur still fires inside failClosed.

5. comment-batch-scorer.ts `computePreLlmRoomSignals`: toxicityScore (mean HF scores), slurPrevalencePct (% HF>=50), authorRecidivism (max comments by single handle), algorithmicAmplification (views/likes ratio from post metrics).

6. prompts-v2.ts `buildBatchPromptV3(enriched, preLlm, mode)`: builds system prompt via `buildReframeFewshotSystem` which injects STEP-1 RULER + SEVERITY-ANCHORED bullet + WORKED EXAMPLES into the base v3 system text via .replace anchors. The .replace call THROWS if any anchor fails to match. User prompt: [POST_ENVIRONMENT] block with platform, surface, post text, engagement metrics, room emotion line (`aggregateRoomEmotion`, suppressed if <3 emoji-using comments), sponsoredLine, algorithmicAmplificationLine, authorRecidivismLine, plus ANCESTRY block (X-permalink only), plus [COMMENTS] numbered list with per-comment `buildCommentLine` emitting HF flag when score>=30. All free-text sanitized via `sanitizeBatchField` (double-pass fence-token stripping + control char removal).

7. ai/client.ts `callAI`: single model `openai/gpt-oss-20b` via proxy at api.feelingwise.org. Max concurrent fetches capped at 5. maxTokens=BATCH_MAX_TOKENS (2048) for the batch call. jsonMode=true; on refusal retries once without response_format. Optional per-call `onCallMeta` sink (2026-09-02) hands the caller its own attempt's finish_reason / completion_tokens from inside the response handler; the `lastCallMeta` module global races with concurrent calls and cannot serve this.

8. comment-batch-scorer.ts `parseJSON`: 3-tier extractor: raw JSON.parse, markdown-stripped, then char-by-char balanced-brace walker with string-literal awareness and underflow guard. When all 3 tiers return null OR the parsed object has no comments array, a tier-4 salvage (`salvageTruncatedComments`, 2026-08-18) extracts individually-complete `{...}` verdict objects from inside the `"comments": [` array of a max_tokens-truncated reply (the cut-open trailing object never balances and is skipped, so no fake verdicts). Salvaged verdicts proceed as a normal parse; the never-emitted indices flow to truncatedIndices → cancelled-batch-truncated; a truncated-away `environment` falls to label 'unknown'. Only a reply with no salvageable verdict fails closed, and when that reply's finish_reason was 'length' the batch retries ONCE at BATCH_TRUNCATION_RETRY_MAX_TOKENS (4096) before giving up. This is narrow by design: a confirmed cut with nothing salvageable is a total loss of a paid call, any other unparseable reply is a refusal or shape fault a repeat call reproduces (2026-09-02). (Original root-cause note for the owner-observed `provider-unparseable-json` class: output hit maxTokens=2048 → a json_validate refusal from Groq (the provider until 2026-09-21) → no-JSON-mode retry returned the truncated raw → balanced-brace tiers all nulled → complete verdicts were discarded with the cut one.)

9. comment-batch-scorer.ts per-comment normalization loop: for each parsed item, validates index bounds, validates technique against VALID_TECHNIQUES set (defaults 'none'), clamps severity 0-10, applies the target_present gate (shame-attack with target_present===false → genuine-opinion sev<=3; a non-boolean field falls through to the code-side `hasPresentTarget` + `detectDehumanization` check, which also downgrades), extracts neutralizedText string (non-empty string only).

10. comment-batch-scorer.ts truncatedIndices detection: any 1-based index with no entry in byIndex after the parse loop is added to truncatedIndices.

11. comment-batch-scorer.ts fills comments array to childrenCount with byIndex.get(idx) ?? {technique:'none', severity:0, sentiment:'neutral'} defaults.

12. comment-batch-scorer.ts `applyOverrideGates` loop: for each comment, calls the pure gate with (verdict, harm_floor, text, mode). Gates in order: (a) identity-slur → shame-attack sev=Math.max(existing,8) action='hide'; (a2) Child-mode profanity floor: an under-flagged profanity comment → technique='profanity' sev 6, no hide (routes to soften); (b) sev>=8 + profanity match → action='hide' (no technique change); (c) coded-harm + not-yet-flagged → technique/sev from codedHarmVerdictFields, action='hide' for violence/self-harm/sexual/doxxing; (d) RAGE_FORMAT_OPENING regex + not-yet-flagged → misleading-format sev=Math.max(existing,6); (e) HF>=70 + (non-flag OR sev<floor) → shame-attack sev=max, floor=(HF>=90?9:HF>=80?8:7); (f) ad-hominem top-category + non-flag + sev<6 → shame-attack sev=Math.max(existing,6).

13. comment-batch-scorer.ts room aggregation: sentiment counts computed from POST-override verdicts. dominantTechnique picks the most common non-'none'/non-'neutral' technique. LLM-emitted room label validated against VALID_LABELS (defaults 'unknown').

14. comment-batch-scorer.ts `computeDiscourseQuality`: 100 - mean HF score on negative-sentiment comments.

15. comment-batch-scorer.ts Phase 2 enrichments: `applyRule13Enrichment` (authorRecidivism>=3 AND shame-attack/scapegoating + negative → severity = min(9, sev+1)); `applyRule14Enrichment` (amplification=high AND roomLabel=pile-on → forensicNarrative='platform routed child to hostile environment').

16. comment-batch-scorer.ts `cacheBatchResult` (only if !result.failed).

17. content/index.ts result returned; parallel `scoreRoom` call kicked off (buildRoomPrompt → separate LLM call at maxTokens=400, parsed by parseRoomAnalysis).

18. content/index.ts fail-closed branch: splits escalated verdicts (sev>=7 OR action=hide) from sev=0 defaults (→ CANCEL_LOG). A hide-tier escalation uses the shared exact-identity hide terminal before FORENSIC_LOG; other escalations write FORENSIC_LOG directly. cap-exhausted skips CANCEL_LOG for non-escalated. Both emitted shapes carry the frozen parent-room fields.

19. content/index.ts per-comment verdict routing loop: truncated + no escalation → CANCEL_LOG; isManipulative + action=hide → shared exact-identity hide terminal + outcome-based FORENSIC_LOG; isManipulative + rewrite-on → flaggedToRewrite; isManipulative + rewrite-off → FORENSIC_LOG; non-manipulative + profanity when `blanketProfanitySoften(settings, platform)` (the `soften-swearing` toggle, which the child preset seeds ON, OR `strictLanguage`; mode is not consulted directly) → profanitySoften; else → PASS_LOG.

20. content/index.ts parallel rewrite pass: inlineRewrite used directly if present; else neutralizeText called per-comment. Both paths run validateRewrite (ten guards). Duplicate cross-comment rewrite guard `findDuplicateRewriteIndices` blanks identical rewrites for distinct originals. Each VALIDATED reframe is also primed into the shared `processingCache` via `primeReframeCache` (keyed by `verdictCacheKeyInput`, the same key the per-post pipeline uses) so opening that comment on its own permalink — where it flows through the per-post pipeline as a focused tweet — reuses the reframe instead of re-analysing un-rewritten (known-issues M30). `primeReframeCache` swallows every error (best-effort cache prime, never a protection path). The batch prints its stats as `[FW batch-rewrite]` / `[FW profanity-soften]` / `[FW comment-hide MISS]` console lines on every flush, plus once-per-session cap / auth-class lines.

20b. Anchor sharing: the marker loop publishes each verified or recovered comment element into `resolvedAnchorByPost` and the swap loop reuses it, so a comment is resolved against the DOM once per flush.

21. content/index.ts scoreRoom result awaited and merged into ENVIRONMENT_LOG.

22. Room attribution outcome: every in-place overwrite of a bucket's room (`seedRoomContextFromPost` in comment-batch/queue.ts) is classified by `content/room-attribution-outcome.ts` (room-changed / room-regressed / filled / idempotent) and persisted fire-and-forget to `chrome.storage.local['commentRoomMutations']` with a redacted exemplar ring (`ROOM_MUTATION_EXAMPLES_MAX` 8; the exemplar still keeps the raw bucket key, known-issues M90a); the Issues tab summarizes it.

comment-scorer.ts (`scoreAndRankComments`) is ONLY used by video-pipeline.ts (the legacy comment path), NOT by the BATCH path in content/index.ts.

## Data flow (through this subsystem)

1. PlatformAdapter DOM extraction -> PostContent[]. Parent observations (including an X focused reply without `parentVideoId`) seed the bounded `platform:parentId` identity cache; child comments enter a `pendingBatches` bucket keyed by parent id and reuse only cached caption/url/author. TikTok's empty-caption feed fallback scopes its flat comment read to the current video container, so a virtualized neighbour's comment cannot enter this boundary with the current video's parent id; permalink fallback remains document-scoped because its panel is a sibling of the focused video.
2. Debounce timer fires -> `flushBatch(parentVideoId)` -> `takePendingBatchForFlush`. The pending bucket is deleted, while bounded parent identity remains available to later batches; one prepared room snapshot feeds successful comment records and the environment record.
2b. flushBatch room fallback: when bucket.videoUrl='' (caption record never arrived — TikTok profile browsing), roomFromPermalink(bucket.permalinkUrl, parentVideoId) (src/content/record/post-url.ts) derives postUrl+roomAuthor from the /@author/(video|photo)/<id> page URL stamped at bucket creation; gated on the URL id EQUALLING the bucket key so a stale permalink never stamps the wrong room. The derived identity is remembered for later batches.
3. flushBatch -> resolvePromptLanguage (settings.outputLanguage or CLD3 auto-detect) -> language string
4. flushBatch -> viewport gate filterToViewed (content/index.ts) -> filtered PostContent[]
5. flushBatch -> buildEncounterForFlushBatch -> X-permalink Encounter with rendered ancestry, dedicated TikTok/Instagram/YouTube/Facebook Encounter, or degraded legacy fallback when required signals are absent
6. Encounter -> scoreBatch(encounter, mode) (comment-batch-scorer.ts)
7. scoreBatch -> computeBatchCacheKey -> cachedBatchResult -> cache HIT returns BatchScoreResult immediately
8. cache MISS -> enrichWithHarmFloor(encounter): per-comment computeHarmFloor + filterProfanity (slur) + detectEmojiPile + detectRepetition -> enriched Encounter with harm_floor stamps
