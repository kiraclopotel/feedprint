## Purpose

The parent review surface for FeelingWise. Reads the entire forensic chain from IDB on load, groups records into post/comment trees, filters them through up to 13 simultaneous filter axes (driven since 2026-08-01 by a left filter rail — grouped, collapsible axes with live click-through counts), and renders the resulting feed as a signed-chain timeline with per-card actions (Confirm/Dispute/Recheck). The Activity timeline is FeelingWise record/timestamp order, not proven platform impression order. The LANDING tab is Activity (`useState<TabId>(() => 'activity')` in the shell); Overview is the second tab button (`OverviewTab.tsx` + pure `overview-data.ts`): a hero figure (the count caught that day, carrying its own 7-day sparkline and delta) over a one-line hidden/marked split and a context clause, the feed-balance bar (same arithmetic as Statistics), the day as 30-min-gap sessions, the served-surface (feedSource) split, a most-served-sources view, and an hour-by-day heat grid; every figure drills into Activity via `recordIds`. Popup `#hash` deep-links still land on the pre-filtered Activity feed. Secondary tabs surface exposure analytics, behavioral patterns, calibration statistics, the chain-integrity ledger, operational event health, and chain export/backup.

## Inputs

ForensicRecord[] from forensics/store.getRecords() (IDB, oldest-first), preceded by the newest-400 page from getRecordsFirstPage() for the first paint; archived month count from archive-reader.listArchiveMonths() and the archives themselves (loadArchivesOldestFirst) on manual cross-month Verify; author escalations from forensics/analytics.computeAuthorEscalation over the loaded records and author profiles; ForensicStats from forensics/store.computeStats() over the loaded records, folded with the summaries of archived months not loaded (archive-summary.foldSummariesIntoStats) (flagged-only technique/platform counts); LicenseInfo from storage/license.getLicense(); Map<string,ParentFeedback> from forensics/store.getAllParentFeedback(); IntegrityResult from forensics/chain-integrity.verifyChainIntegrity(); CalibrationResult from core/calibration.calibrate(); SW-owned signing metadata via GET_SIGNING_METADATA; settings (mode, uiLanguage, features) from storage/settings.getSettings(). OperationalEventsPanel independently reads telemetry stores, selector health, content-free protection health, scan log, AI-call/video-AI telemetry, chain integrity, and getForensicDeliveryStatus().

## Outputs

Parent feedback (confirmed/disputed) written back to forensics/store.addParentFeedback(); theme preference written to storage/settings.saveSettings(); PIN-gated reset sent as RESET_FORENSIC_CHAIN; recheck sent as RECHECK_RECORD; staged restore sent as RESTORE_FORENSIC_BACKUP with the parent PIN in the payload (the service worker verifies it, same gate as reset); export/backup blobs pushed to browser download; view-original sends OPEN_ORIGINAL to the service worker, which registers the tab in inspection-registry.ts BEFORE tabs.create so the content script on that tab runs in inspection mode (no hide, cover, collapse, rewrite or marker). Dashboard never owns a destructive chain cutover or first-use signing-key generation.

## Invariants & contracts

- Attestation reaches the feed (2026-08-10): FeedCard renders a "Protections on at capture" chip row from configSnapshot.enabledFeatures and a red settings-unreadable note from configSnapshot.settingsReadFailed, so the hashed switch-state proof is visible in the Activity feed, not only in exports. - groupRecordsByPost group key: a comment uses `${platform}:${parentVideoId}`; a comment with no parentVideoId (or empty-string, falsy) becomes its own standalone group on its globally-unique id; the parentVideoId branch is platform-scoped so two unrelated posts sharing a raw id across platforms can't merge. NEW (M29): a POST/VIDEO record with NO stamped parentVideoId (an X focused tweet — twitter.ts stamps parentVideoId only on its CHILDREN) adopts its OWN platform id, derived from postUrl via the shared `platformPostIdFromUrl` (src/core/platform-post-id.ts — the same id format the adapters stamp), as the key — BUT only when ANOTHER record references that key: a comment, or (on records written before 2.5.0) a video-context record whose parentVideoId is the analysed post's own id. The two-pass pre-scan collects every `${platform}:${parentVideoId}` in the set. This merges a focused tweet with its reply thread instead of orphaning it under a post-less group, without merging unrelated home-feed re-sightings (nothing references it → stays standalone on r.id). FB ids are not URL-derivable → those posts stay standalone. (group-records.ts)
- anyFilterActive causes showFlat=true — every matched record is individually visible; tree view only renders when no filter is active (components/activity-filters.ts isAnyFilterActive, ActivityTab). Invariant enforced by tests/unit/ui/dashboard/components/dashboard-count-filter-invariant.test.ts

## How it ACTUALLY works

On mount (Dashboard.tsx load()): repairRelegatedPositions() runs first; phase A reads the newest 400 records through getRecordsFirstPage() into `firstPage` and clears the spinner (only the Activity feed reads `firstPage`; every other tab shows the loading shell, the header chip and every rail count show a pending glyph, `archiveLoading` / `countsPending`); phase B runs the authoritative getRecords() (a failed read sets the failed-read empty state via lastRecordReadFailed(), never an empty chain), stats, licence / settings reads, SW signing metadata, then the post-paint verifyChainIntegrity() whose valid result mints the verify watermark, calibrate(), listArchiveMonths() for the archived-month count, and computeAuthorEscalation(). Manual Verify runs the full walk and verifyChainIntegrityAcrossMonths() over the archives. Signature/hash/link failures are never auto-re-anchored. Visibility-change and window-focus events re-pull records/stats/feedback and extend the verify from the watermark (see Invariants). ActivityTab holds 12 filter states plus search, composed by a single per-record predicate `passes(r, except?)` (intersection — order-free): what (FeedFilter) ∧ place ∧ who ∧ when ∧ severity ∧ kind ∧ technique (with canonicalization) ∧ hiddenCategory ∧ safetyBucket ∧ recordIdsSet ∧ roomUrl ∧ hourRange ∧ search. `except` skips one rail axis so railCounts tallies click-through counts per option. Result is reversed (chronological newest-first). groupRecordsByPost then groups the filtered list by `parentVideoId ? ${platform}:${parentVideoId} : id`: a post record (kind==='post'||'video') lands as group.postRecord only when the group has none yet; subsequent post-kind records land in children. Groups sort by latest group timestamp, so the display is record/timestamp order rather than a verified impression sequence. PostGroupCard re-partitions postKindRecords from the group into evidenceRecord (has videoContext, worst verdict wins) + captionRecord; the primary card is evidenceRecord ?? captionRecord ?? postKindRecords[0]. Comments paginate at COMMENT_PAGE=8, collapsed by default. FeedCard derives shell (tiktok/youtube/facebook/x/instagram) from platform+kind, resolves viewOriginalUrl via the fallback chain, renders metrics from record.metrics falling back to environment.metrics, and derives media/comment status without adding signed fields. buildGrowthByRecordId groups by growthIdentity (anchorUrl for comments, parentVideoId for posts), pairs first/last metric-bearing sightings, emits only when deltas exist and sightings>=2. DashHeader reads records[records.length-1] for last-record timestamp (correctly newest-last). Issues-badge watermark advances when operational tab is opened. ExportTab applies applyExportGate before every export. Backup is encrypted-optional; restore is performed in the SW realm and clears the dashboard signing cache only when a matching wrapped key committed.
