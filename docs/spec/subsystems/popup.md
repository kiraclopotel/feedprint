# Subsystem: popup

> Traced from code. Confirmed defects live in the defect register `known-issues.md`, which is not part of the public copy; [KNOWN-LIMITS.md](../KNOWN-LIMITS.md) carries what a reader outside the project needs from it. Re-read against the code in the 2026-08-23 objective audit (spec-drift.md items 98 to 100).

## Purpose

The 380px Chrome extension popup (or, through the detach affordance in the header, a standalone `popup.html?detached=1` window opened with `chrome.windows.create`, where `body.fw-detached` relaxes the fixed width) is the parent-facing control surface for FeelingWise. It runs the first-time setup wizard (mode selection, PIN creation, recovery phrase; no license step, a key goes in the License tab), displays a hero figure for actions taken today over a quiet secondary line, plus per-page coverage, hosts the License tab for key management (with a parent PIN set, Save and Remove open the same PinOverlay as Settings and honour the grace window, so a child cannot downgrade the install to the free tier from the popup; lock: tests/unit/ui/popup/popup-keys-pin-gate.test.tsx), and provides a PIN-gated Settings panel for all feature toggles, per-platform overrides, theme, output language, and video-understanding (BETA). Since 9 Oct 2026 Home holds one button, Open your record: the "Read this for me" button came off on the owner's word, and nothing in the popup arms `content/read-this.ts` any more (spec: `read-this.md`). Lock: `tests/unit/ui/popup/popup-read-card.test.tsx`. All mutations write through to chrome.storage.local via storage/settings.ts and storage/license.ts; nothing is computed in the popup itself beyond UI state.

## Key files

- src/ui/popup/Popup.tsx - Single entry point; exports `computeStatusStates`, `computeAiBannerState`, `PopHeader`, `HomeTab`, `KeysTab` (used by tests). Mounts as `<Popup />` via createRoot on #root. Contains SetupWizard, HomeTab, KeysTab, SettingsPanel (also exported for tests), BlockAiHashtagEditor, PinOverlay, PinDigits, Toggle, StatusDot, PopHeader, PopTabBar components.
- src/ui/popup/popup-design.css - Scoped production CSS for .fw-popup (380px frame). No media queries; theme is driven via data-theme on :root (tokens.css). The old chip-editor, .pop-body and .provider-step rules are gone.
- src/storage/settings.ts - Provides getSettings/saveSettings/setPin/verifyPin/applyPreset/isFeatureEnabled/getFeatureValue; FWSettings interface (schema v14); migrateSettings (v0 to v14 chain); module-level cache with onChanged invalidation.
- src/storage/license.ts - Provides getLicense/setLicense/clearLicense/isValidLicenseKey/parseLicenseKey/dailyCapForTier/isUncappedTier; LicenseInfo + LicenseTier types; LICENSE_TIER_CAPS (all paid tiers = 2000/day $5/mo).
- src/storage/presets.ts - childPreset/teenPreset/adultPreset/presetForMode; seeds FeatureToggles on install, migration, and explicit mode-switch.
- src/ui/popup/coverage-map.ts - describePageCoverage(hostname, pathname, lang); called by HomeTab to show the parent what FW actually covers on the active tab.
- src/ai/client.ts - Exports probeProxy(licenseBearer): ProxyProbeResult ('ok' | 'revoked' | 'unknown'). Called once per popup open when tier != free, and again whenever the stored tier/secret changes. Hits /v1/models with a 5s abort; definitive results cache for 5 min keyed by bearer, 'unknown' is never cached. Result drives the license-dot color and, since 2026-08-03, the chip's own text when the probe could not complete.
- src/ui/shared/theme.ts - applyTheme/eagerApplyStoredTheme/subscribeToSystemThemeChanges/resolveTheme. Called at module-load time (eagerApplyStoredTheme) and inside Popup useEffect.
- src/i18n/index.ts - resolveUiLanguage; UiLanguage/ResolvedUiLanguage types. 'auto' resolves to 'ro' if navigator.language starts with 'ro-', else 'en'.
- src/i18n/popup-strings.ts - POPUP_STRINGS[lang] typed table (PopupStrings interface); every user-visible string in the popup must come from here.

## Inputs

chrome.storage.local (all FWSettings keys + 'fw_license_key') read on every popup open via getSettings()+getLicense(). Active tab URL read via chrome.tabs.query for coverage-map. OS theme via window.matchMedia. Browser language via navigator.language for 'auto' UI-language resolution. chrome.storage.onChanged events from other FW surfaces while the popup is open: the `RELOAD_ON` set covers eight keys (dashboardTheme, uiLanguage, features, mode, strictLanguage, hideUnrewritable, aiAnalysisEnabled, fw_license_key). The `textCapReached` pause marker is read from storage for the Home tab's pause line.

## Outputs

Writes to chrome.storage.local via saveSettings(partial) on every toggle/mode/language/theme change. Writes 'fw_license_key' via setLicense/clearLicense. Writes the salted PBKDF2 PIN hash via setPin (storage-license.md, SEC-G5). Writes preset seed (features + presets) on setup completion and mode switch. Opens chrome://extensionpage dashboard.html (with optional #section hash) via chrome.tabs.create. Fires probeProxy network request to api.feelingwise.org/v1/models (zero tokens) for license status only.

## Invariants & contracts

- Setup screen exits to 'main' iff settings.parentPin is truthy (Popup.tsx) — a user who skipped the license key but set a PIN lands on main, not stuck in setup.
- PIN gate: with a PIN set, `requestSettings` opens the Settings panel through PinOverlay unless `isPinGraceActive()` (15 minutes after a correct entry, stored in chrome.storage.session), in which case it enters directly; the same grace applies to the License tab's Save and Remove. Leaving Child mode and the chain reset / restore always demand the PIN regardless of grace. Direct screen='settings' without a PIN is only possible when parentPin === ''.
- PIN recovery and change (2026-08-23, UX-I18N-A11Y-1): setup step 4 shows an 8-character recovery phrase (XXXX-XXXX, 32-symbol alphabet without 0/O/1/I) exactly once with an "I wrote it down" button; finishSetup stores only its salted PBKDF2 hash (fw_pin_recovery, via setRecoveryPhrase) after setPin. PinOverlay has a "Forgot PIN?" link that opens PinRecoveryForm: phrase + new PIN + confirm, calling resetPinWithRecoveryPhrase, which shares the PIN attempt throttle, accepts lowercase and a missing dash, and does NOT open the grace window; an install with no stored phrase sees pinRecoveryNone (honest: uninstall is the only exit). The phrase is not consumed by use. Settings has a "Parent PIN" group with a Change PIN row (ChangePinPanel: current PIN via verifyPin, new PIN, confirm); a legacy install with no phrase gets one generated and shown once after a successful change. Locks: tests/unit/storage/pin-recovery.test.ts, tests/unit/storage/popup-change-pin.test.tsx.
- PIN attempt throttle (2026-08-10): verifyPin in settings.ts allows five free consecutive misses, then each further miss locks the gate for an escalating window (30 s doubling, capped 15 min); a correct entry clears it; state persists in chrome.storage.local (fw_pin_attempts) so SW respawns and popup reopens do not reset it; every gate (popup, dashboard modal, SW RESET_FORENSIC_CHAIN re-verify) shares the one implementation. While locked even the correct PIN is refused. Unreadable throttle state fails closed since 2026-08-23 (SEC-G5): verifyPin refuses and pinLockRemainingMs reports one base window until storage answers again. pinLockRemainingMs drives the lock copy in PinOverlay. Lock: tests/unit/storage/pin-throttle.test.ts.

## How it SHOULD work

On popup open (attached, or detached through the header affordance): read settings + license in parallel, resolve UI language, apply theme, fire a background proxy probe if tier != free, and show either the SetupWizard (no PIN set) or the main screen (PIN set). The main screen has two tabs: Home (today hero + secondary line + coverage card + dashboard CTA) and License (key entry/removal + cap info). A PIN-gated Settings panel is reachable from the header cog icon. All changes write immediately to chrome.storage.local and reload state. The status-dot chip reflects the live license state (green=paid+ok, amber=free, red=revoked). The setup wizard is a flow of up to 4 steps: welcome → mode pick → PIN create → recovery phrase (shown once); Relaxed ends on the mode pick. Completing it saves mode+preset+PIN. It has no license step: setup always runs with no key, so no screen of it names the AI reading (lock: tests/unit/ui/popup/a-free-setup-says-no-ai-word.test.tsx).

## How it ACTUALLY works

Module load: eagerApplyStoredTheme() fires async chrome.storage.local.get before React mounts (Popup.tsx). React mounts, Popup() renders with settings=null → shows loading text using POPUP_STRINGS[lang].loading; if the initial reload rejects, it renders a localized retry state instead of staying blank. useEffect on mount calls reload() = Promise.all([getSettings(), getLicense()]); on resolution: sets screen based on settings.parentPin (Popup.tsx), calls applyTheme again (Popup.tsx). Second useEffect installs chrome.storage.onChanged listener for dashboardTheme+uiLanguage changes (Popup.tsx). Third useEffect subscribes to OS matchMedia when dashboardTheme='system' (Popup.tsx). Fourth useEffect fires probeProxy(bearer) when tier != free (Popup.tsx), where bearer is constructed as `fw-${license.tier}-${license.secret}` (Popup.tsx). computeStatusStates(license, proxyProbe) derives licenseState (Popup.tsx). openDashboard() builds hash from section param and calls chrome.tabs.create (Popup.tsx). SetupWizard step 3 (finishSetup): calls saveSettings({mode, features: presetForMode(mode)}) FIRST, then setPin — settings before PIN, because wizard re-entry is gated on parentPin being empty, so a PIN persisted ahead of a failed settings write would lock the install at Teen defaults with no retry path (D5 fix, 2026-08-04). SettingsPanel.toggle() reads current feature, flips enabled, writes full features object via saveSettings (Popup.tsx). SettingsPanel.togglePerPlatform() uses isFeatureEnabled to read current per-platform state before writing (Popup.tsx). Mode switch in Account card calls applyPreset(m) then saveSettings (Popup.tsx); since 2026-08-05 (D6) a click that would LEAVE Child mode first demands the PIN via an inline PinOverlay regardless of the 15-minute grace window (modeSwitchRequiresPin: mode==='child' && target!=='child' && parentPin set — gating only, mode psychology unchanged; entering Child stays one click), mirroring how the destructive chain-reset gate ignores grace. The Adult mode explanation copy also states that flagged media is recorded-not-hidden and ads are logged-not-treated-as-manipulation regardless of toggles (D7). Under the segmented control a computed one-line state (2026-08-05, laydown 4.1) reads "Standard <mode> protection" when the grid equals the current mode's preset (modeSwitchResetsToggles(features, mode) === false) or "<mode>, customized" with a PIN-free "Reset to standard" button that re-applies applyPreset(mode) — divergence between mode label and grid is made visible instead of silent. Theme picker calls applyTheme immediately (DOM update before storage write) then saveSettings (Popup.tsx). Language selects (uiLanguage, outputLanguage) write immediately via saveSettings on change (Popup.tsx). After every write the onChange callback calls reload() to re-read storage and update all state (Popup.tsx). BlockAiHashtagEditor reads stored hashtags from settings.features['block-ai-content'].value.hashtags (Popup.tsx); if missing, falls back to DEFAULT_AI_BLOCKLIST_HASHTAGS (Popup.tsx); saves by writing the full features object patch (Popup.tsx).

## Data flow (through this subsystem)

1. chrome.storage.local → getSettings()/getLicense() (storage/settings.ts, storage/license.ts) → [settings: FWSettings, license: LicenseInfo]
2. [settings, license] → Popup() useEffect:reload() (Popup.tsx) → React state [settings, license, screen, tab]
3. screen='setup' → SetupWizard (Popup.tsx) → step 0-3 local state [mode, pin]
4. SetupWizard step 3 finishSetup() (Popup.tsx) → saveSettings({mode, features}) + setPin(hash) + setRecoveryPhrase(hash), in that order → chrome.storage.local
5. screen='main' → Popup() useEffect:probeProxy(`fw-${tier}-${secret}`) (Popup.tsx, ai/client.ts) → ProxyProbeResult → computeStatusStates() (Popup.tsx) → licenseState DotState → StatusDot color
6. HomeTab (Popup.tsx) → chrome.tabs.query({active,currentWindow}) → tab.url → describePageCoverage(hostname, pathname, uiLang) (content/coverage-map.ts) → PageCoverage | null → coverage card render
7. HomeTab hero → settings.totalNeutralizedToday (all-time subline totalNeutralizedAllTime); secondary line → metricsHiddenToday / totalChecksToday → display; click on either → openDashboard(section) → chrome.tabs.create({url: 'dashboard.html#section'}) (Popup.tsx)
8. KeysTab saveLic() (Popup.tsx) → setLicense(licDraft.trim()) (storage/license.ts) → chrome.storage.local.set({'fw_license_key': canonical}) → onChange() → reload() → state update
9. KeysTab removeLic() (Popup.tsx) → clearLicense() (storage/license.ts) → chrome.storage.local.remove('fw_license_key') → onChange() → reload()
10. SettingsPanel toggle(id) (Popup.tsx) → updateFeature(id, cur => ({...cur, enabled})) (fresh-read single-feature merge) → chrome.storage.local.set(partial) → onChange() → reload()
11. SettingsPanel togglePerPlatform(id, platform) (Popup.tsx) → isFeatureEnabled(settings, id, platform) → updateFeature(id, cur => ...) → onChange() → reload()
12. SettingsPanel pickTheme(next) (Popup.tsx) → applyTheme(next) [DOM: document.documentElement.dataset.theme] + saveSettings({dashboardTheme: next}) → onChange() → reload()
13. SettingsPanel uiLanguage select onChange (Popup.tsx) → saveSettings({uiLanguage}) → onChange() → reload() → resolveUiLanguage(settings.uiLanguage) (i18n/index.ts) → lang → I18nProvider re-render
14. SettingsPanel mode seg-btn click → onModeClick(m) → PIN gate (leaving Child) → resolveModeClick(settings, m) → 'confirm': inline confirm row (pendingMode) | 'apply': applyPreset(m) (storage/settings.ts) → {features, presets} → saveSettings({mode, features, presets}) (a Child write also forces the capture flags off) → onChange() → reload(); Reset-to-standard skips the confirm
15. chrome.storage.onChanged (Popup.tsx) → any RELOAD_ON key → reload(); dashboardTheme additionally → applyTheme()
16. Home tab pause lines → chrome.storage.local textCapReached / mediaMonthlyCapReached / imageContextBudgetExhausted → pausedText 'daily' | 'monthly' | media pause

## 2026-09-07: the swear mask replaces the swear rewrite

Ordinary swearing is no longer rewritten. `maskProfanity` (src/core/profanity-filter.ts) stars each matched vulgar word in place and changes nothing else; no model call, no cap, no tier. Posts: the pipeline branch that called the rewriter now masks, after the dehumanisation and narrated-violence gates, with `detectionMode` `profanity-mask:<n>` and `aiSource` `rules`; the harm-laundering check left with the rewriter (a mask cannot drop content). Comments: the collected passing-but-profane comments are masked through the swap path and never hidden. The popup row is "Mask swearing", outside the paid group, on every tier; Strict language still implies it. Slurs, attacks and the identity tiers are untouched. The record still carries the `profanity` label at severity 4 until the decision block writer lands (Stage 2), when a mask reads as `pass` with `household.mask` true. Design: docs/design/POLICY-TABLE-2026-09-07.md section 2.
