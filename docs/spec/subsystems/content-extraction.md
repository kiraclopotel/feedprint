# Subsystem: content-extraction

> Traced from code. Confirmed defects live in the defect register `known-issues.md`, which is not part of the public copy; [KNOWN-LIMITS.md](../KNOWN-LIMITS.md) carries what a reader outside the project needs from it. Re-read against the code in the 2026-08-23 objective audit (spec-drift.md items 17 to 25); the Key files list follows the content/index.ts split and is maintained with it.

## Purpose

Turns rendered social-media DOM into PostContent[] records and routes each record toward either the per-post LLM pipeline (posts/captions) or the comment-batch flush path (comments). Enforces the chain-mirror invariant: only content that crossed the viewport produces a chain record. Manages all dedup stamps, queue priority, anchor fingerprinting for DOM-recycle defense, and session-verdict caching to avoid redundant LLM calls on re-detected nodes.

## Inputs

Raw DOM mutations: NodeList of added HTMLElement nodes from document.body MutationObserver (interceptor.ts). Platform adapters (src/content/platforms/*.ts) receive those nodes and return PostContent[] — one record per extracted post, caption, or comment, carrying: id (platform-side post code or crypto.randomUUID() fallback), text, author, platform, kind (post/video/top-comment/reply/reply-to-reply), domRef (WeakRef<HTMLElement>), parentVideoId (bucket key for comments), depth (1-indexed), feedSource, platform_specific (per-platform metrics + flags + surfaceKind). Inputs also include: scroll velocity from ScrollVelocityTracker, settings from chrome.storage.local (getSettings), license tier (getLicense), feature flags (isFeatureEnabled, isDevFlagEnabled).

## Outputs

To analysis subsystem (src/analysis/pipeline.ts): PostContent via ProcessingQueue.processFn — the pipeline receives PostContent and returns PipelineResult. To comment-batch scorer (src/analysis/comment-batch-scorer.ts): Encounter objects built by encounter-builder.ts, via scoreBatch() and scoreRoom(). To service worker (forensics subsystem) via chrome.runtime.sendMessage: FORENSIC_LOG, PASS_LOG, CANCEL_LOG, ENVIRONMENT_LOG, SCAN_LOG, NEUTRALIZATION_COMPLETE messages with chain payloads. To DOM (injector subsystem): injectIntoElement / injectCollapseOrHide / injectAdHide / markOnlyElement / swapCommentTextInPlace / hideCommentAsFallback calls for visible UI mutations. To chrome.storage.local: selector-health counters (fw_selector_health), extraction-canary state (fw_extraction_canary), content-free protection-health snapshots (fw_protection_health_v1), pending-locate request (fw_pending_locate). To diagnostics module: bumpCounter/setGaugePeak calls.

## Invariants & contracts

- Chain-mirror: every DOM node that crosses the viewport (IntersectionObserver 10% threshold OR synchronous getBoundingClientRect backstop at flush time) produces exactly one chain record. Comments that never enter the viewport produce zero records and their adapter dedup stamps are cleared via unmarkPostsForReExtraction for re-extraction on back-scroll. (viewport-tracker.ts)
- Anchor stability: a verdict must not be applied to the wrong DOM node. computeAnchorKey (queue.ts) builds id::text[0:200] at enqueue; verifyAnchorMatch (src/forensics/anchor-revalidation.ts) recomputes at render time; mismatch → CANCEL_LOG, no UI mutation. (queue.ts, index.ts)
- failClosed symmetry: when scoreBatch fails, every comment in the bucket that lacks a deterministic harm-floor escalation gets a CANCEL_LOG record. No comment silently passes without a chain record on LLM failure. Cap-exhausted (free tier) is excluded from CANCEL_LOG to avoid flooding the chain. (index.ts)
- dedup-stamps are 1:1 with classification: a comment stamped fwCommentSeen='true' that is dropped by the viewport gate or cooldown has its stamps cleared (via IO on re-entry) so re-extraction fires on back-scroll. Without clearing, that comment would be permanently un-classified — a chain-mirror violation. (viewport-tracker.ts)
- Session forensic dedup: shouldLogForensic(text) returns true at most once per text per content-script lifetime (bounded set, 2000 entries); the key is the text alone, so a second comment with identical text but another author or id is skipped at the record level and, since 636f83e, has the prior verdict re-applied to its node (known-issues M106). Prevents duplicate chain records on re-detection of the same post text. Cancel records (cancelled-stale/mid-flight/dom-*/batch-*) never consume this entry — they dedup via the separate cancel set (shouldLogCancelForensic), so a cancelled item is treated as not-yet-handled and gets full handling (record + UI) on re-encounter. (forensic-gate.ts)
- Act-on-re-encounter: a verdict that completes after its DOM node scrolled away (pipeline mid-flight cancel, or render-gate dom-gone/dom-recycled suppression) is stored in sessionLateVerdictByPostId; the next detection with the same exact classification key applies it directly to the fresh node — no re-scoring, no new chain record (the cancelled-* record already carries the analysis). A confirmed concern with no rewrite in hand routes to the MARK floor (markOnlyElement), never nothing. (late-verdict-cache.ts sessionLateVerdictByPostId, index.ts applyLateVerdictDirect, tests/unit/content/post-path/cancelled-verdict-reencounter.test.ts)
- Classification-key cohesion: session verdict caches and queue coalescing include id, platform, author, kind/parent/depth, text, context, and normalized `is_sponsored`; the queue also includes classification generation and queue kind. A late sponsored marker or changed content can never inherit/fan out an organic verdict merely because `post.id` stayed the same. Post-comment parent linkage still uses parentVideoId as the room bucket key; comment depth is 1-indexed in PostContent and converted to 0-indexed in ForensicRecord by chainCommentDepth. (late-verdict-cache.ts `sessionVerdictKey`, queue.ts `classificationDedupKey`, chain-depth.ts)
- Authoritative PASS continuity: both a fresh `post-llm-*` PASS and a `pre-llm-cache-pass` backed by that earlier detector result enter the bounded exact-input session PASS set. Capacity refusal, provider failure, too-short content, and other unadjudicated pre-LLM exits never do. A virtual remount of the same classification input therefore bypasses both the Child cover and queue, while changed text/context/sponsorship remains eligible. (late-verdict-cache.ts `isAuthoritativeSessionPassReason` / `sessionPassPostIds`)
- Render-gate before UI mutation: anchor verification fires before injectIntoElement / injectCollapseOrHide / markOnlyElement. X and TikTok post hide/collapse recovery carries a runtime-only WeakRef to the original feed area, then searches that area immediately and once on the next frame for exactly one matching stable post id, full body, and known author. Synthetic TikTok ids, changed content, duplicates, detached areas, and wrong-area matches retain the honest cancel. No adapter extraction or provider call occurs during recovery. Other DOM-recycle recovery uses tryRecoverDomRecycledAnchor / tryRecoverCommentAnchor. (index.ts recoverExactPostInterventionAnchor; dom-recycle-recovery.ts tryRecoverExactPostInterventionAnchor)
- Comment HIDE remount ownership: non-Facebook hides accept only their connected extraction anchor and re-check the extracted body before mutation. Facebook may recover one unique body inside the exact parent post by full text + depth and author when available; its Facebook-only final live-body equality ignores paragraph newline separators so extractor text and concatenated DOM `textContent` agree without weakening identity checks. In Child mode, `ChildProtectionManager.prepareMutation(post, recoveredAnchor)` mounts the replacement cover before retiring the old owner, then the hide terminal settles that new owner. A recovery miss keeps protection and records a flag, never a hidden outcome. (`index.ts` `applyCommentHide`; `child-first-protection.ts` `protectAt` / `prepareMutation`)
- Pending swaps applied AFTER marker render: swapCommentTextInPlace is collected in pendingSwaps and applied only after all marker renders complete, so verifyAnchorMatch's textContent comparison sees the original (enqueue-time) text, not the rewrite. (index.ts)
- DM privacy boundary: isPrivateMessageSurface() stops recognized private URLs at the top of `_processNodes`; each platform adapter rejects candidates whose ancestor is a recognized chat dialog before reading candidate text or touching FW dedup stamps; the interceptor's returned-record filter remains defense-in-depth. Chat open/close tracking invalidates pending surface work without stopping extraction of public siblings. (interceptor.ts, platforms/adapter.ts, platforms/facebook.ts, platforms/twitter.ts, platforms/tiktok.ts, platforms/instagram.ts, platforms/youtube.ts)
- context-guard: safeSendMessage becomes a no-op once MV3 context-invalidation is detected; reportProcessingError stops the queue after 3 consecutive context errors. (context-guard.ts)
- Protection-health privacy: the live-cover heartbeat stores no post text, URL, media source, or item identifier. It keeps at most 20 surface-session aggregates for the current day and becomes stale after 15 seconds without a live content-script heartbeat. (protection-health.ts)
- Post-intervention diagnostics persist counts only: requested/concurrent/applied/suppressed/failed, delivery receipt state, and a PASS-after-request correlation. Post ids remain console-only and never enter `fw_diagnostics`. The 60-second correlation window and 200-key in-memory bound affect diagnostics only. (diagnostics.ts, index.ts)
- Queue admission matches the renderer's five AI fetch slots. Below-viewport work keeps prefetch priority but may occupy at most four ProcessingQueue slots. This prevents a second hidden FIFO from defeating the queue and leaves one local admission place for newly enqueued visible post work; independent video joins share the same provider gate but no longer sit behind five extra requests from this queue. (queue.ts, ai/client.ts)

## How it SHOULD work

At `document_start`, the bootstrap applies an opaque root curtain before the asynchronous mode read and retains it only for explicit Child mode; absent mode follows the existing fresh-install Teen default and releases. The main content script waits for `document.body`, starts the interceptor, runs the initial extraction/protection pass, and acknowledges readiness; a 5-second bootstrap timeout prevents a permanent blank page if that handoff fails. On each MutationObserver fire, Child mode passes added nodes to the platform adapter synchronously so protection mounts in the same microtask; document-wide extraction-canary probes are skipped on that pre-paint path. Teen and Adult accumulate nodes in a Set and drain it on the next rAF tick (≤60/s). Platform adapters reject recognized chat-dialog candidates before reading text or adding dedup stamps, while public-feed siblings continue. In Child mode, a first-seen batched comment is synchronously covered before the 1.5s debounce starts; an uncached post/caption is covered immediately before ProcessingQueue enqueue; cached ACT replays are covered until their final DOM mutation. Post owners share one feed-unit lease. The cover preserves layout, blocks interaction, stays muted against `volumechange`, and self-heals after same-host reconciliation. Benign outcomes and verified rewrites/collapses restore the original media baseline; final hard hides preserve mute. A `finally` settles every comment handle through a verified rewrite, safe hide fallback, benign release, or retained cover when no safe terminal can be confirmed. For comment records (kind top-comment/reply/reply-to-reply with parentVideoId), the comment enters a per-parentVideoId bucket; the bucket is flushed 1.5s after last arrival or when it reaches COMMENT_BATCH_MAX_SIZE=5, whichever comes first. At flush time the viewport gate filters to viewed comments; the remaining posts are assembled into a rich Encounter and sent to scoreBatch. Post/caption records use the ProcessingQueue, which admits at most five jobs and caps non-visible jobs at four so provider work for the current item is not trapped behind a hidden FIFO; visible-soon keeps prefetch priority in the remaining lanes. It coalesces only identical classification inputs, promotes an exact-input queued/in-flight duplicate to sticky visible state when the viewport reaches it, fans one result to matching remounted DOM instances, and reports every dropped owner for cover cleanup. Session caches use exact classification identity, including sponsorship, and are cleared on mode change. onPostDetected also stamps observedSequence, viewportSeenAt, and surfaceSessionId.

## How it ACTUALLY works

`bootstrap.js` applies a synchronous root curtain before the mode read and retains it only for explicit Child mode. `init()` resolves the adapter, waits for `document.body`, initializes media owners, creates `ProcessingQueue(processPipeline, onProcessingResult, onDrop)` and `ContentInterceptor(adapter, onPostDetected, onSurfaceChange, childEnabled)`, starts the synchronous initial-body pass, then signals bootstrap readiness. Child mutation batches extract synchronously; Teen/Adult batches drain once per animation frame. Periodic rescans cover non-YouTube surfaces. X/TikTok/Facebook/Instagram route watchers key on pathname+search: the immediate callback increments the classification generation, cancels pending media/comment work, retains connected Child covers on public routes, and releases them on private routes; the delayed pass strips stale stamps and rotates ownership through fresh extraction. Every awaited comment-batch phase re-checks generation before record or DOM output. Mode changes clear all session verdict shapes, invalidate old classifier generations, and synchronously rescan every mode; every generation bump (route, mode, strict-language) also calls `ProcessingQueue.invalidate` so queued stale posts are aborted and removed and in-flight ones are aborted and flagged, their eventual result discarded. Each invalidated post writes a cancelled-stale CANCEL_LOG (dedup-gated); in Child a post still connected and in the viewport on a public surface is re-stamped for the new generation and re-enqueued at the top of the visible tier so its cover is never released raw, while every other invalidated post settles as a stale owner (lock: tests/unit/content/post-path/queue.test.ts, tests/unit/content/queue-invalidate-on-generation-bump.test.ts); image context rescans again after its async paid-tier restart resolves. Chat candidates are rejected before adapter text/dedup access, with a final returned-record filter as defense-in-depth. Early initialization exits and failures also signal readiness, while bootstrap owns the 5-second fail-open backstop.

`onPostDetected` stamps source/account and impression data first. X assigns a real status id only when one top-level relative or X/Twitter absolute status permalink atomically names the same author as the article header. A weak per-slot snapshot couples that identity to the body element and text; an unmatched or one-sided body/identity transition falls back to a local synthetic id, author `unknown`, no parent binding, and no external URL, so protection continues without sealing a false attribution. Permalink ancestry uses that same resolver. A comment-kind record with `parentVideoId` enters `enqueueCommentForBatch` through the synchronous Child cover. Every other observation seeds the bounded `platform:parentId` room cache before any session-verdict/pass/hide return; this includes ordinary post/video records and an X focused reply with no `parentVideoId` whose visible replies point back to it. Non-batched observations then use the session fast paths: a fresh or persistent-processing-cache PASS bypasses the cover after its first authoritative result, cached ACT is covered until its DOM mutation, and uncached work is covered before entering the per-post processing queue. Unadjudicated failure/cap/gate exits never become session PASS. `first_protection` and `protection_terminal` perf spans measure mount latency and time under an item cover when diagnostic capture is enabled.

Route identity and rescans: `computeRouteKey(platform, pathname, search)` keys a route on the pathname plus an allowlist of query keys (`ROUTE_KEY_QUERY_PARAMS`: youtube `v` and `list`, facebook `v`; every other platform is pathname-only), so a search-param-only `replaceState` is not a route change. On a route change the interceptor calls `onRouteChange('route')` synchronously (content/index.ts hands in `clearPendingBatchesForRouteChange`, which drops the pending comment buckets and the remembered room identity), then schedules `_rescanAfterRoute` after RESCAN_DELAY_MS (400 ms), which emits `'route-settled'` and re-processes the body. Which stamps survive a rescan: the route rescan and the Child turn-on rescan clear only `data-fw-processed` and `data-fw-comment-seen` document-wide (`_clearExtractionStamps`); `fwCaptionEmitted`, `fwTileSeen`, `fwReelProcessed`, `fwPermalinkPostId` and TikTok's `emittedVideoIds` survive, so TikTok / IG captions, IG tiles and reels do not re-extract on a rescan while FB and X posts do. Chat-overlay state machine: when a chat overlay opens the pending rAF batch is cancelled and `_pendingNodes` cleared (`onRouteChange('chat-open')`); when it closes a full-body reprocess runs (`'chat-close'`). The periodic 3 s rescan carries a perf sampler that prints one `[FW perf] periodic-rescan` console line per 15 s window while ticks run.

`enqueueCommentForBatch` viewport-observes the row, creates or updates the parent bucket, and flushes after the debounce or batch cap. `takePendingBatchForFlush` removes that bucket, records the flush time, applies the id-gated permalink fallback, and freezes the room fields consumed by comment and environment records while the bounded identity remains for later batches. `flushBatch` applies output-sink and viewport gates, builds the platform-specific Encounter, runs `scoreBatch` plus the optional parallel `scoreRoom`, routes comment records to forensic/pass/cancel messages, validates and applies rewrites/hides/markers, and emits `ENVIRONMENT_LOG` from the same prepared room snapshot. Every hide producer goes through one outcome terminal. It revalidates the extracted body, hands an exact Facebook remount to the Child owner when necessary, proves the hidden DOM state, and only then writes `action:'hide'`; a miss writes `action:'mark'`.

## Data flow (through this subsystem)

1. Platform DOM mutations → MutationObserver callback (interceptor.ts) → Child sends added nodes directly to `_processNodes`; Teen/Adult accumulate `_pendingNodes`
2. Teen/Adult `_pendingNodes` Set → rAF drain tick (interceptor.ts) → Array<Node> batch
3. Array<Node> batch → _processNodes(nodes) (interceptor.ts) → isPrivateMessageSurface/shouldSkipNodeAccumulation gates → adapter.extractPosts(nodes); each adapter excludes recognized chat-overlay candidates before candidate text/dedup access; every returned record then passes the `carriesFwInjectedText` gate (interceptor.ts), which drops a record whose element carries FeelingWise's own injected text (a rewrite, placeholder or marker) so FW never re-classifies its own output
4. adapter.extractPosts(nodes) (platforms/twitter.ts, facebook.ts, tiktok.ts, instagram.ts, youtube.ts) → PostContent[] with id, text, author, kind, domRef, parentVideoId, depth, platform_specific. X binds a real id and permalink ancestry only to a same-author top-level status permalink whose identity/body slot transition is coherent; uncertainty stays synthetic, anonymous, parentless, and URL-less. Instagram reads the author, the shortcode and the permalink only from links that speak for the same card (outside comment `<ul>`s and nested `<article>`s), and its two URL-driven surfaces (`/p/` permalink, `/reels/`) refuse a read whose container still holds the previous post: a body already recorded under another shortcode emits nothing, and a body whose mounted comment permalinks name a different post stays protectable under a synthetic id, author `unknown`, no parent, no URL. The tile grid attributes a tile to a page owner only when the page itself corroborates the handle (a profile self-link outside any navigation landmark); an uncorroborated single-segment route, including any Instagram adds, falls back to author `unknown` rather than signing the route word as a person.
5. PostContent[] → _processNodes loop: stamps el.dataset.fwProcessed='true', calls onPostDetected(post) (index.ts)
6. onPostDetected(post) (index.ts): isCommentKind && parentVideoId? → enqueueCommentForBatch(post) (batched comments never enter ProcessingQueue); kind='video'|'post'? → seedRoomContextFromPost: seeds the bounded `roomContextByParent` cache (500 entries) and merges into an EXISTING bucket only (buckets are created by enqueueCommentForBatch via newPendingBatch); then → session cache checks → queue.enqueue(post, computeViewportInfo(el))
7. enqueueCommentForBatch(post) (comment-batch/queue.ts): cooldown check → observePostForViewport(post) → bucket.posts.push(post) → schedule flushBatch (1500ms debounce, 800 ms per-parent floor, or immediate at batch cap=5)
8. queue.enqueue(post, viewportInfo) (queue.ts): compute anchor key, priority, staleMs → push QueueItem → _drain()
9. _drain() (queue.ts): prune stale items (abort controllers; items in state 'visible' are exempt from the age check, since they are on screen under their cover; index.ts onQueueDrop writes a cancelled-stale CANCEL_LOG for every stale or size-cap drop before releasing the cover, lock: tests/unit/content/post-path/queue.test.ts, tests/unit/content/record/child-first-protection-queue-drop.test.ts) → sort visible-soon before visible before scrolled-past → enforce five total/four non-visible admission with one local place for newly enqueued visible work → processFn(post, signal) = pipeline.process(post, signal)
10. pipeline.process(post, signal) → AI call through the proxy (ai/client.ts) → PipelineResult {action, neutralized, analysis, aiMeta, cancelKind}
11. PipelineResult → onProcessingResult(post, result) (result-apply.ts): SCAN_LOG emit, then a result with no visible intervention settles its cover through `settleProtection` (record `verdict`); a stale-generation result settles with `write-cancel`; action branches → verifyAnchorMatch(computeAnchorKey(post), post, post.domRef) → match/dom-recycled/dom-gone
12. match → DOM injection (injector.ts: injectIntoElement/injectCollapseOrHide/markOnlyElement) + shouldLogForensic(text) gate → retained record via sendHighStakesForensicLog → accepted/retry-buffered/context-lost receipt → applied/suppressed/failed diagnostic terminal → service worker
13. flushBatch(parentVideoId) (comment-batch/flush.ts): viewport gate filterToViewed(bucket.posts) → buildEncounterForFlushBatch(posts, caption, language, permalinkUrl) → scoreBatch(encounter, mode) + parallel scoreRoom(encounter, mode)
14. scoreBatch result → per-comment verdict loop: CANCEL_LOG (truncated/failed) / FORENSIC_LOG (manipulative) / PASS_LOG (neutral) + flaggedToRewrite collection
15. flaggedToRewrite → Promise.all(neutralizeText calls or inline rewrite) → validateRewrite (ten guards) → findDuplicateRewriteIndices → pendingSwaps / hide terminal
16. hide-tier verdicts → applyCommentHide (hideCommentAsFallbackTerminal, proven before record); pendingSwaps → applyCommentRewriteTerminal after the marker render loop
17. ENVIRONMENT_LOG emit → service worker → forensics store (environment record)

## Known divergences (Phase-1 flags)

- **[med]** X focused tweet double-classification path. The focused tweet (depth=0, kind='post') at onPostDetected seeds the pendingBatches bucket (caption/author) AND falls through to queue.enqueue at line 1914. It receives a full per-post LLM pipeline call and FORENSIC/PASS chain record. The batch bucket it seeded will flush its children with the focused tweet's caption as context. If the focused tweet flags, shouldLogForensic prevents a duplicate forensic record for the SAME TEXT (deduped by text hash), but if the same tweet is re-detected after an SPA stamp-strip, a second pipeline call is queued (sessionPassPostIds prevents only PASS re-queuing, not HIDE/neutralize re-render). This is intentional by design per twitter.ts comments but the dual path is not documented as a known dual-record risk. — src/content/index.ts 1914
- **[low]** URL cohesion check in buildEncounterForFlushBatch uses exact href equality (currentUrl === expectedUrl). On X permalink with a fragment or query-param change between bucket fill and flush (e.g. photo modal opens → URL gains /photo/1), the check fails and falls back to enrichLegacyEncounter (losing ancestry context). No warning is logged when this occurs, making it a silent degradation. — src/content/record/encounter-builder.ts
- **[low]** COMMENT_BATCH_MAX_SIZE=5 cap (5 comments per LLM call) is applied before viewport filtering. When the bucket fills to 5 before ANY of those 5 comments crosses the viewport, flushBatch fires, filterToViewed returns 0 comments, the entire bucket is dropped, stamps are cleared. The next MO tick re-extracts those comments and they accumulate a new bucket. This creates a re-fill loop until at least one comment enters the viewport. On a slow connection with lazy-loaded comment section, this can spin many times. — src/content/index.ts 677-688
- **[low]** The focused tweet is emitted with kind='post' (depth=0 via depthToKind). onPostDetected seeds the batch bucket using `post.parentVideoId ?? post.id`. For the focused tweet, parentVideoId is undefined (twitter.ts only sets it for children-of-focused), so the bucket key is the focused tweet's own id. Comments under it stamp parentVideoId=focusedTweetId (same id). So the bucket key matches — this alignment works correctly. But if the focused tweet arrives AFTER its first child comment (race between article mount order), the bucket is first created by the comment's enqueueCommentForBatch call with videoAuthor='unknown'; the focused tweet's seed then overwrites caption/author. No data loss, but the ordering dependency is implicit and unguarded. — src/content/index.ts 1859-1891
- **[low]** computeAnchorKey falls back to `${id}::${author}::__nocaption__` for empty-caption posts (queue.ts). On TikTok music-only videos where multiple creators post the same empty-caption 'original sound' clips, if id extraction fails (crypto.randomUUID() fallback), author is extracted correctly. Two different creators' videos produce distinct anchor keys. But if BOTH id AND author extraction fail (post.id=UUID, post.author='unknown'), the key is `<uuid>::unknown::__nocaption__` — unique only by UUID, which is already per-extraction. isDegenerate flag is set (queue.ts) to signal this case, but no caller currently uses it to tighten the render gate. — src/content/post-path/post-queue.ts
- **[low]** Pre-rewrite-harm-floor-gate.ts is used by the legacy TikTok comment pipeline (runCommentPipeline / video-pipeline.ts). The BATCH comment path in index.ts flushBatch has its own inline harm-floor logic using detectDehumanization + detectHarmLaundering + filterProfanity directly. The two paths are not unified behind the pre-rewrite gate, creating dual maintenance surface for the same hide-vs-rewrite decision. No functional divergence known, but drift risk. — src/content/protection/pre-rewrite-harm-floor-gate.ts, src/content/index.ts
- **[med]** dom-master (dom-master/tier-runner.ts, shape-detector.ts) is architecturally a universal extraction layer. In practice, only some platform adapters call extractCommentRows; others still use inline querySelectorAll loops. The dom-master is not uniformly adopted across all 5 platforms, so its rotation-diagnostic and selector-health integration is partial. This means DOM-rotation drift on adapters not using dom-master produces no rotation-diagnostic.ts warning. — src/content/platforms/dom-master/tier-runner.ts
- **[low]** The COMMENT_BATCH_MIN_FLUSH_INTERVAL_MS=800ms rate-limit uses the `lastFlushAtByParent` Map (comment-batch/queue.ts), which is cleared by `clearPendingCommentBatchState` on every route change and runtime policy change but grows unbounded within one route; each entry is a string to number pair. — src/content/comment-batch/queue.ts
- **[med] RESOLVED (M6)** pendingBatches Map is module-level and never cleared on SPA navigation. Stale buckets for previous-URL parentVideoIds accumulate. Their timers fire (flushBatch), bucket is fetched, deleted, URL cohesion check may save from a wrong Encounter (if expectedUrl != currentUrl), but the PASS/CANCEL records still emit with the previous URL's parentVideoId and roomUrl. On X SPA nav between permalink A → permalink B, old A-bucket comments may flush under B's session. — src/content/index.ts. **Fix:** `clearPendingBatchesForRouteChange()` (index.ts) clearTimeout's every bucket timer and clears pendingBatches + lastFlushAtByParent; ContentInterceptor calls it (via the new optional `onRouteChange` constructor arg) at the start of `_rescanAfterRoute` (interceptor.ts), so a stale bucket can no longer flush after navigation. Also clears the unbounded lastFlushAtByParent growth flagged above (index.ts) on each route change. Test: tests/unit/content/comment-batch-route-clear.test.ts.
- **[low]** scrollableAncestorCache (viewport-tracker.ts) is a WeakMap keyed on HTMLElement. The doc-comment states 'when the element is removed from the DOM the WeakMap auto-evicts'. This is incorrect: WeakMaps evict entries only when the key is GC'd, not when removed from DOM. A virtualizer that keeps detached nodes alive (pooling) will cache stale scroll-container relationships. — src/content/post-path/viewport-tracker.ts
- **[med] RESOLVED (M22)** safeSendMessage (context-guard.ts) returns `Promise<unknown> | undefined`. Discarding that response could lose any retained record. **Fix:** every FORENSIC_LOG / BLOCKED_LOG / PASS_LOG / CANCEL_LOG / ENVIRONMENT_LOG now dispatches through `sendHighStakesForensicLog()`, which adds a stable delivery id/capture time, awaits the SW durable-enqueue response, and buffers an explicit or ambiguous live-context failure for bounded replay. The helper returns `accepted`, `retry-buffered`, or `context-lost`; ordinary callsites ignore it, while outcome-sensitive hide/collapse diagnostics await it. Canonical payload shape unchanged. Test: tests/unit/content/record/forensic-log-retry.test.ts.
